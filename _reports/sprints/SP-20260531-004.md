# Sprint Report — scan-suite self-inventory (`/scan:scan-coverage`) (2026-05-31)

## TL;DR

WarpOS has 40+ "scan" health-checks, and the master "run every check" command (`/scan:full`) was a **hand-typed list** that silently drifted from the real set of checks — so some checks existed but never actually ran in the full sweep. We built a tiny check that **audits the scan suite itself** (every scan must be on the master list, or on a short "intentionally excluded, here's why" list), and it immediately caught **4 real checks that were being skipped**. We wired them back in. The full sweep can't silently drift again.

## What we did (ELI5)

**The goal:** kill the "we have a safety check, but nobody actually runs it" problem.

- `/scan:full` is WarpOS's "run every health check" button. Its list was maintained by hand, so it drifted — a check would get built and never added to the button (the docs literally admitted this happened once).
- We added **`/scan:scan-coverage`** — a check whose only job is to confirm every other scan is either on the `/scan:full` button **or** on a short "left off on purpose, with a written reason" list. It's the suite checking itself.
- Running it caught **4 checks that existed but were being skipped**: `role-parity`, `scaffold-coverage`, `etc-harness`, `ingest-firewall`. We added them to the button. (One read-only, informational scan — `warpos-layer-diff` — is intentionally left off, with the reason recorded.)
- We deliberately **did not merge checks together**. Using our "ponder" + "reasoning" thinking tools, we found the suite only *looks* redundant — e.g., two scans that seemed like duplicates actually do different jobs. The real problem was *legibility*, which the new self-check fixes — so merging would have been churn + risk for no gain.

**What's different now:** the full health sweep is honest. It can't silently skip a check, because a check now guards exactly that.
