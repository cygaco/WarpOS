# E-MC-READINESS-ANALYSIS-001 · Track 3 — Advanced Edge-Case / Adversarial-Input / Race Prediction

**tl;dr:** **31 edge cases enumerated, 10 high-severity.** Across WarpOS's shipped command + dispatch + install + scaffold + sprint surface, the failures that will bite a real consumer cluster into **five structural classes**: (1) **raw `JSON.parse` of a BOM/CRLF file** on every install/update hot path — the *known* WarpOS bug class, present unguarded in `update.js`/`transaction.js` even though sibling code already strips BOM; (2) **non-atomic shared-file writes with no per-entity lock** in sprint state (`fs.js#writeYaml`) and dispatch locks anchored to `process.cwd()` — both corrupt under the operator's default "parallelize everything" posture; (3) **input validation that only guards the new-repo path, not the in-place path** the Console actually drives (slug, name, reserved Windows device names); (4) **guardrail fields that are WRITTEN but never READ** (`minUpgradeableFrom`, RI-007 closed-sprint status); (5) **no path-traversal containment** on the applied-asset `dest` in the production updater (the test harness guards it; production does not). Detection exists for many of these only at release/on-demand, never per-commit. Analysis only — no code changed.

- **Epic / track:** E-MC-READINESS-ANALYSIS-001 · Track 3 (adversarial / Murphy edge-case + race prediction)
- **Date:** 2026-06-16 · **Author:** Alex α (autonomous) + 3 parallel sub-agent audits · **Type:** findings only, evidence-grounded, no changes
- **Method:** read the four surfaces in full (dispatch wrappers + safety kernel + concurrency lock personally; install/update, scaffold/bootstrap/canon, sprint orchestration via dispatched lean-return audits), cross-referenced `.claude/project/memory/recurring-issues.jsonl` (RI-001..RI-007). A case already covered by a test or a fail-closed guard is **down-ranked** (listed under "Already handled").
- **Consumer model:** a non-technical founder running a scaffolded product, OR the Master Console driving the engine **headless + programmatically + in parallel** (the higher-stress driver — it omits flags a human would pass, retries on slow runs, and feeds capsules from canonical).

## The five structural classes (the through-line)

| Class | What it is | Where it lives | Why the Console makes it worse |
|---|---|---|---|
| **C1 · BOM/CRLF raw read** | `JSON.parse(readFileSync(f,"utf8"))` with no BOM strip / no CRLF normalize | install/update hot path, canon intent read | Console (de)serializes JSON via PowerShell → UTF-8 BOM; fresh-migrated repos ship CRLF |
| **C2 · non-atomic write + no lock** | raw `fs.writeFileSync` to a shared file, no temp+rename, no per-entity lockfile | sprint `fs.js#writeYaml`, `active-sprints.yaml`, dispatch `concurrency-lock` (cwd-anchored) | Console runs sprints/updates **in parallel by default** → concurrent writers tear state |
| **C3 · validation only on the new-repo path** | slug / name / reserved-name checks gate `createProductRepo` but NOT the in-place scaffold | `scaffold/app.js`, `bootstrap/phases/setup.js` | Console drives the **in-place** path (repo already installed) — the unguarded one |
| **C4 · written-but-never-read guardrail** | a safety field is emitted at release but no consumer reads it | `minUpgradeableFrom`, RI-007 closed-sprint status | Console skips many versions + omits `--sprint` — exactly what these guards were for |
| **C5 · no path-traversal containment** | applied-asset `dest` joined + written with no "stays under root" assertion | `update.js` apply/backup/rollback | Console pulls capsules from canonical — a malformed/garbled capsule escapes the repo |

## Top-5 most-likely-to-bite-a-real-consumer

Ranked by **probability × blast-radius** for the Master Console driver specifically (headless, parallel, omits flags, feeds capsules, on Windows/PowerShell).

1. **RI-007 — `/sprint:full` without `--sprint` mutates a CLOSED sprint** (`full.js:1744-1747` + `paths.js:194-203`). The Console drives `/sprint:full` *programmatically* and is the most likely caller to omit `--sprint`. Confirmed **open**; mitigation today is a human convention ("mint first") the Console won't follow. **A new feature request is silently absorbed into a finished sprint and never built.** One status check closes it.

2. **BOM-prefixed JSON breaks the install/update hot path** (`update.js:79-86` + `transaction.js:342,347`). The Console (de)serializes JSON via PowerShell, which writes a UTF-8 BOM; fresh-migrated repos ship CRLF. `readJSON` swallows the error → **whole-repo mis-classification**, and `readHeader`/`readSnapshot` *throw* → **rollback un-recoverable mid-crash**. The codebase already knows this class (`repo-role.js:110` strips BOM); the updater just doesn't. One helper fixes it.

3. **Sprint state corruption under parallel resume** (`fs.js:237` raw write + **no lock anywhere** in `scripts/sprint/`).
