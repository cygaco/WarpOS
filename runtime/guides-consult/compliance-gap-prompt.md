# Consult: compliance/legal coverage gap-check for a newbie-founder launch library (2026)

You advise an AI-driven product factory that takes total-newbie solo founders (no legal team, no budget for one except true escalations) from prototype to launched product. It ships (a) plain-language founder-facing launch guides and (b) agent-grounding compliance rule-sets that an automated QA reviewer applies to built features. Products are typically: consumer/prosumer web + mobile apps, often AI-powered (LLM features), US-based founders selling globally, Stripe/app-store monetization, Supabase/Firebase-class infra.

## What ALREADY exists (do not re-cover; gap-check against it)
Founder guides: privacy/GDPR (consent banner, privacy policy, DSAR export button, delete-account flow incl. processor cascade + anonymize-vs-delete, marketing consent/unsubscribe, vendor DPAs, data-location/transfers, under-13 age-gate avoidance); legal (ToS + provable acceptance, subscription auto-renewal/cancellation law incl. state ARLs/ROSCA, declare-every-data-point matching reality, IP/trademark/AGPL, LLC, accessibility — WCAG 2.2 AA + EAA-in-force note + ADA lawsuit warning); app-store submission (privacy labels, privacy manifest, IAP rules); security (RLS lockdown, secrets, rate limits, prompt injection); email (CAN-SPAM basics, unsubscribe); onboarding (COPPA amended-rule escalation, age gates); payments (entitlements, webhooks).
Agent rule-sets (train the QA reviewer): privacy-data (three-way code↔policy↔store-label match, SDK collection duty, data minimization, named processors, Apple 5.1.1(v) in-app account deletion, which-regime FLAG); consumer-subscriptions; app-store policy; IP/trademark.

## Identified candidate gaps — judge each: real gap? how expensive? what shape (founder guide vs agent rules vs both vs skip)?
1. **Data-rights OPERATIONS** (vs the existing build-level checklist): identity verification before fulfilling a DSAR/deletion (how much verification is right-sized for a small app? over-verification is its own violation), statutory clocks per regime (GDPR 1 month, CCPA 45 days, others 2026), request intake channel + audit log of requests/fulfillment, deletion-from-backups honesty (what is the accepted answer for backup retention windows?), legal-hold/billing-records exceptions, processor cascade mechanics, Google Play's account-deletion requirements (in-app + WEB link + Data Safety deletion declaration — confirm current state), agent rules like "deletion must be honest (no soft-flag-only)", SLA timer ops for a solo founder.
2. **Breach/incident notification duty**: GDPR 72h-to-authority + when users must be told, US state breach-notification laws (50-state patchwork — what's the practical newbie playbook? AG notices?), processor-breach handling (Supabase/Stripe breached — what's the founder's duty?), a right-sized incident runbook (detect → contain → assess → notify → document) for a one-person company, cyber insurance worth it?
3. **Minors beyond avoidance**: the factory's current stance is "age-gate to 13+, escalate children's products to lawyers". Is that stance right? What MUST still be built even for a 13+ app (age gate honesty, teen design codes — UK AADC, US state AADCs/teen social-media laws as of 2026 — which are in force/enjoined?), and where exactly is the escalation line?
4. **AI-product compliance** (the factory ships AI products!): EU AI Act obligations for a small genAI app (chatbot transparency "you're talking to AI", AI-generated-content labeling/deepfake disclosure, GPAI vs deployer duties — what applies to an app CALLING OpenAI/Anthropic APIs vs building models, current enforcement timeline), FTC AI-claims substantiation, AI + children, AI training-data/user-content terms (can the founder train on user data? what must ToS say?), state AI laws (CO AI Act? CA?). What's guide-worthy NOW vs noise for a tiny app?
5. **Data retention schedule**: right-sized defaults for a small app (what to keep how long: logs, analytics, deleted-account residue, invoices) and whether this deserves its own guide or folds into the data-rights ops guide.
6. Anything ELSE a 2026 launch is commonly bitten by that the library misses entirely (think: TCPA/SMS consent if products send texts, CASL, cookies/ePrivacy enforcement trends, US state privacy-law spread — universal opt-out signals/GPC honoring?, DSA basics for consumer platforms?, export controls?, sales tax/VAT — or is that out of scope for legal-compliance guides?). Rank by (likelihood × cost) for a small consumer app; mark anything that's noise.

## Structure question
Current plan: ONE new founder guide "DATA_REQUESTS" (DSAR + deletion + retention ops), ONE "INCIDENT_RESPONSE" (breach runbook + notification duty), extend the privacy/legal guides with pointers, and add agent rule-sets: data-rights-ops, breach-notification, minors/age-assurance, AI-transparency. Critique: merge/split differently? What anchors in a launch pipeline (project-start / while-building / pre-launch gate / post-launch)?

For every recommendation: the single most expensive mistake it prevents, and the one-sentence rule that prevents it. Be opinionated; flag where your knowledge may be stale vs 2026 and say what to verify. Structured markdown.
