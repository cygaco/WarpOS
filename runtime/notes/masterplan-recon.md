## 2. Decision-Making System

**Spec:** `.claude/agents/00-alex/.system/policy/decision-policy.md` (`paths.decisionPolicy`). Authoritative file (no separate `_warpos` source in the working tree). Loaded by Beta every invocation (after `judgement-model.md`); Alpha consults directly in solo mode.

**Decision classes:**
- **Class A — Decide automatically:** implementation-level, reversible, low blast radius. Beta DECIDEs without scoring; Alpha (solo) decides directly. (Component structure, file naming, local state shape, helper extraction, test org, minor UI within the design system, equivalent library API, log verbosity.)
- **Class B — Decide, score, document if architectural:** meaningful technical. Beta scores options against the rubric and returns DECIDE with one recommendation. When it affects **architecture, dependencies, data model, security, or deployment**, also flag `OPEN_ADR: true` (Alpha drops an ADR in `paths.policy/adr/`). (New dependency, schema change, new pipeline stage, API surface, auth-flow mods, deploy config, cross-file refactor.)
- **Class C — Escalate to user:** strategic, irreversible, business-sensitive, or trust-affecting. Beta returns ESCALATE with **one recommended answer**, not a menu. (Pricing, positioning, sensitive data handling, compliance posture, vendor lock-in, payment architecture, launch readiness, data retention.) A legitimate Class C resolution can be **state-conditional** ("decided at the decision point based on the state then") — DP-gap #29, 2026-05-30.

**Scoring rubric (Class B)** — NOT a numeric 0-N sum. It is a **weighted-criteria table**, weights set by the current product stage (`paths.currentStage`):
```
| Criterion          | Weight @MVP     | What to look for                         |
| Product fit        | high            | serves a value in PRODUCT_MODEL.md       |
| Simplicity         | high            | easy first-read, fits the mental model   |
| Reliability        | high            | works in prod on the happy path          |
| Reversibility      | high            | change our mind in a week, cheaply       |
| Security           | mandatory pass  | serious concern → reject regardless      |
| Speed-to-ship      | medium          | ships this cycle                         |
| Cognitive cost     | medium          | new user mental load                     |
| Operational burden | medium          | ongoing maintenance created              |
| Cost               | low @mvp        | infra/API/vendor (→medium at beta)       |
| Ecosystem maturity | medium          | boring/well-supported vs novelty         |
```
Tiebreaker (scores within ~10%): pick the simpler + more reversible. Output rule: present ONE recommendation, never a menu. "Stage shifts the weights" — at beta Reliability→mandatory-pass, at production Cost→high + Performance enters. There is also a **tech-introduction rule** (4 conditions to add any new service/framework/dep; default answer = "use what we have") and a **fallback rule** (uncertain → simplest reversible decision, proceed, one-line rationale).

**Escalation red lines (always escalate):** irreversible ops (delete data, force-push, remove branches); spec-semantics changes (what users see/feel/are promised); spend ≥ $5; external-facing actions (push, deploy, publish, email, social); credentials/secrets; contradicting a CLAUDE.md rule; pricing/positioning/compliance; sensitive PII; payment architecture; public launch readiness.

**β consultation protocol:** Beta returns exactly one of **DECIDE | DIRECTIVE | ESCALATE**, logged to `paths.betaEvents`; only ESCALATE reaches the user (prefixed `ESCALATE:`). A **two-gate authority** rule (2026-05-14) says a Beta DECIDE does NOT override the Claude Code auto-mode classifier on harness-safety blocks — surface to the user with one plain-text sentence instead of retrying.

## 8. GPT 5.5 Dispatch Mechanism (COPY-PASTEABLE)

**The pieces:** `scripts/dispatch/catalog.js` (provider/model source of truth) + `scripts/hooks/lib/providers.js` (`runProvider`, the execution bridge) + `scripts/dispatch-agent.js` (the per-role dispatch CLI used by orchestrators). Note: `scripts/dispatch.js` is the **Dispatch Console** (a config-editing TUI: `show`/`edit`/`set`/`backups`) — NOT the prompt-runner. To actually RUN a prompt against a provider you use **`scripts/dispatch-agent.js`** (or `runProvider` directly). Authoritative doc: `.claude/agents/.system/guides/agent-dispatch-guide.md`.

**(a) Model ID that maps to "GPT 5.5":** provider **`openai`** (CLI = `codex`), model **`gpt-5.5`** (label "GPT-5.5 (flagship)", the OPENAI `defaultModel`). From `catalog.js`:
```js
const OPENAI = { id:"openai", label:"OpenAI", cli:"codex",
  syntaxTemplate:"codex exec --sandbox workspace-write {reasoning} -m {model} -",
  requiresFallback:true, defaultModel:"gpt-5.5",
  models:[ {id:"gpt-5.5", label:"GPT-5.5 (flagship)", contextTokens:1_000_000,
            effortLevels:["low","medium","high","xhigh"]}, {id:"gpt-5.4",…}, {id:"gpt-5.4-mini",…} ] };
```
`PROVIDER_ALIASES` also maps `gpt → openai`. (In `providers.js`, `OPENAI_FLAGSHIP = process.env.OPENAI_FLAGSHIP_MODEL || "gpt-5.5"`.)

**(b) Exact command (the prompt-runner):**
```
node scripts/dispatch-agent.js <role> <prompt-file> [--provider openai] [--model gpt-5.5] > out.json
```
Use a role that natively routes to openai (e.g. `reviewer`/`compliance`), OR force any role onto GPT-5.5 with the documented override `--provider openai --model gpt-5.5`. Under the hood `runProvider` runs codex as: `codex exec --sandbox workspace-write [-c model_reasoning_effort=<E>] -m gpt-5.5 -` (trailing `-` = read prompt from **stdin**) via `execSync`, prompt piped on stdin.

**(c) How the prompt is passed:**
- `dispatch-agent.js` reads the **prompt FILE** you pass as an argument, hands the text to `runProvider`, which **writes it to a temp file then pipes it to the CLI on stdin** (codex `-`). For codex/gemini the prompt is NEVER passed as an argv string to the child.
- **MEMORY/GOTCHA — large prompts go via a FILE, not inline argv.** The whole dispatch path is file→stdin precisely to avoid arg-length overflow (exit 126 on Windows) and bash-escaping. The agent-dispatch-guide cross-provider section: "Codex/Gemini stdin cannot follow file references — inline everything; prompt sizes are 80-180KB and that's expected."
- **Windows cmd.exe stdin bug — never `cat file | codex exec …` from Bash.** The bridge sidesteps it via `execSync` with the temp-file/stdin pattern. providers.js header: "a transport-level bug (e.g. the codex Windows stdin hang) is fixed once, not per-caller. Callers that bypass this re-introduce the bug." → **always go through `dispatch-agent.js` / `runProvider`.**
- Codex flag notes (verified 2026-05-30): `--full-auto` is DEPRECATED (≥0.135) → `--sandbox workspace-write`; `codex exec` is non-interactive so `--ask-for-approval` is rejected; `gpt-5.5` works on Codex 0.135.

**(d) Required env/keys + location:**
- **`OPENAI_API_KEY`** — codex auths via ChatGPT login (`codex login`) OR `OPENAI_API_KEY`. (Gemini's key is the one `providers.js` explicitly reads from `~/.gemini/.env` and injects; for openai, codex picks up its own login/env. The `.env.local` at repo root + `~/.gemini/.env` are the key locations on this box.)
- Config sanity enforced by `scripts/test-dispatch-config.js`; routing parity by `scripts/checks/dispatch-routing-parity.js`; provider smoke by `scripts/warpos/provider-smoke.js` / `scripts/delta-canonical-dispatch-smoke.js`.

**(e) Helper function:** `runProvider(role, prompt, opts)` in `scripts/hooks/lib/providers.js` → returns `{ ok, provider, model, output, fallback?, error? }`. `opts = { timeoutMs (default 120000; bumped to 900000 for xhigh+large prompts), model }`. Per-provider concurrency caps via `scripts/hooks/lib/concurrency-lock.js` (gemini 3 / openai 10 / claude 32); falls back to claude on slot timeout or CLI-missing. Related exports: `getProviderForRole`, `providerAvailable`, `getReasoningEffort`.

**COPY-PASTEABLE TEMPLATE (run from repo root):**
```powershell
# 1. Write the consultation prompt to a FILE (Write tool or Set-Content -Encoding utf8),
#    e.g. runtime\notes\etc-prompt.txt  — file→stdin avoids argv overflow + the cmd.exe stdin bug.

# 2. Dispatch GPT-5.5 (codex) and capture stdout. `reviewer` natively routes to openai/gpt-5.5;
#    the explicit override makes it unambiguous and works from ANY role:
node scripts/dispatch-agent.js reviewer runtime\notes\etc-prompt.txt --provider openai --model gpt-5.5 > runtime\notes\etc-gpt-out.json

# (Output is wrapped per the dispatch envelope. For a neutral, schema-free consult,
#  use the advisor/consult pseudo-roles which skip envelope validation:)
node scripts/dispatch-agent.js consult runtime\notes\etc-prompt.txt --provider openai --model gpt-5.5 > runtime\notes\etc-gpt-out.txt
```
Programmatic alternative (no CLI):
```js
const { runProvider } = require("./scripts/hooks/lib/providers");
const out = runProvider("consult", promptText, { model: "gpt-5.5", timeoutMs: 300000 });
// out.output holds GPT-5.5's text; out.fallback === true means it routed to Claude (codex unavailable).
```
(`advisor`/`consult` are the W-4 pseudo-roles defined in `DEFAULT_AGENT_PROVIDERS` exactly for ad-hoc cross-provider second-opinions — non-Claude, NO strict output schema, envelope validation skipped. Best fit for an `/etc` consultation.)

**VERDICT:** "GPT 5.5" = `--provider openai`, model `gpt-5.5` (OPENAI `defaultModel`, label "GPT-5.5 flagship"), executed through **`scripts/dispatch-agent.js`** → `runProvider` → `codex exec --sandbox workspace-write -m gpt-5.5 -` with the prompt written to a temp file and piped on stdin. Pass the prompt as a **FILE** (file→stdin path avoids exit-126 argv overflow and the Windows cmd.exe stdin bug — never raw `cat | codex`). Use the **`consult`/`advisor`** pseudo-role for a schema-free consultation. Note `scripts/dispatch.js` is the config TUI, not the runner. Copy-paste template + programmatic `runProvider` form above are ready to run from repo root.
