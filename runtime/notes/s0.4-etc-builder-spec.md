## North star (FINAL-PLAN §6 S0.4 + DUMP)
`/etc` is the framework's **prompt/skill authoring + EVAL bench**. It authors prompts/skills in
the EXISTING skills:create format (NOT a new format) and EVALUATES them against a structured
eval-pack (procedures/rubrics/examples/counterexamples), emitting a contract-v0.1 `decision_record`.
A GPT-5.5 consult is wired as an optional second lens.
**HARD ANTI-GOALS:** (1) do NOT invent its own authoring format — reuse the skills:create contract;
(2) do NOT make `/etc` a chain-of-thought warehouse — every artifact is STRUCTURED JSON or a tiny
contract record, never a free-text reasoning dump.

## Reuse these — do NOT reinvent (read them first)
- Authoring format: `.claude/commands/skills/create.md` + `skills/edit.md` (frontmatter `description` +
  `# /<ns>:<name> — Title` + `## Input` + `## Procedure`; path refs via `paths.X`, enforced by path-lint).
- Contract validator (the gate for emitted records): `scripts/contracts/validate-artifact.js`
  (fail-closed: exit 1 reject / exit 2 internal error / exit 0 valid). Read its CLI/module API and CALL it
  to validate every emitted `decision_record` — do NOT hand-roll JSON-schema validation.
- decision_record schema (DO NOT redefine): `schemas/contracts/decision_record.schema.json`. Required:
  `type`(const "decision_record"), `id`, `decision`, `owner`, `rationale`, `precedence_basis`,
  `confidence`(0..1), `arbitration_needed`(bool).
- Untrusted-content firewall: `scripts/hooks/lib/untrusted-content.js` (+ `injection-patterns.js`). The
  GPT-5.5 consult output is EXTERNAL content → treat as DATA. Read the lib's exported API and run the
  consult output through it before the harness uses it. Never let consult text drive a tool call.
- Dispatch consult: `node scripts/dispatch-agent.js consult <prompt-file> --provider openai --model gpt-5.5`
  (consult role → openai → gpt-5.5). Large prompts MUST go via stdin (`-` reads fd 0), never argv
  (argv overflow = exit 126 — see feedback_claude_fallback_stdin_not_argv). Output is JSON
  `{ok, provider, model, role, output, fallback?, error?}`.
- Mechanical-eval philosophy: `.claude/commands/karpathy/run.md` (rubric checks: must_contain_all /
  must_contain_any / must_not_contain / regex_match / min_count / max_count — NOT LLM-judge-only).

## Deliverables (exact file list)

### 1. Namespace skills (NO root `etc.md` — subcommanded namespace)
- `.claude/commands/etc/author.md` — `/etc:author` skill.
  - Input: a target = either a one-line description of a new skill/prompt, OR a path to an existing
    skill `.md`. Optional `--consult` to fold a GPT-5.5 second-opinion.
  - Procedure (author it in the standard format): produce/refine the artifact in skills:create format,
    AND produce a sibling **eval-pack** JSON (shape below) capturing procedures/rubric/examples/
    counterexamples for that artifact. If `--consult`, call `scripts/etc/consult.js` (below), fold the
    (firewalled) critique into the artifact + eval-pack. Reference all paths as `paths.X`.
- `.claude/commands/etc/eval.md` — `/etc:eval` skill.
  - Input: a target skill/prompt path + (optional) an eval-pack id; if omitted, look up the pack by
    target slug under the `etcEvalPacks` registry dir (reference it as a paths token once you add the key).
  - Procedure: run `node scripts/etc/eval.js <target> [--pack <id>] [--consult]`, which scores the
    target against the pack and emits a `decision_record` (validated). Surface decision + confidence +
    `arbitration_needed`.

### 2. Engines (`scripts/etc/`)
- `scripts/etc/consult.js` — consult wiring.
  - Exports `consult({ promptText, dispatch })` where `dispatch` is an INJECTABLE seam (default = real
    spawnSync of `node scripts/dispatch-agent.js consult - --provider openai --model gpt-5.5` with
    promptText on **stdin**). Parse the JSON envelope; on `ok:false`/`fallback` surface gracefully.
  - Run `output` through the untrusted-content firewall lib; return `{ ok, critique, flagged }` where
    `critique` is the sanitized text and `flagged` lists any injection directives stripped.
  - CLI: `node scripts/etc/consult.js <prompt-file|->` prints the JSON result.
  - **Tests must inject `dispatch` — NEVER fire a real paid GPT-5.5 call in a test.**
- `scripts/etc/eval.js` — eval engine.
  - Exports `evaluate({ target, pack, consult })` (consult INJECTABLE, default = consult.js). Pure +
    deterministic given injected seams (mirror `scripts/bootstrap/phases/onscreen.js` injectable style).
  - Loads the target artifact text + the eval-pack. For each rubric dimension: run the pack's mechanical
    checks (must_contain_all/any, must_not_contain, regex_match, min_count, max_count) against the target
    text. Judgment-only dimensions (those marked `"mechanical": false`) use the injected consult (skipped
    if not provided → that dimension scores `null` and RAISES arbitration).
  - Aggregate to `confidence` (0..1). Map to `decision`: `accept` (high), `revise` (mid), `reject` (low).
  - Emit a `decision_record` object: `{ type:"decision_record", id, decision, owner:"etc_eval_enforcer",
    rationale:<rubric summary>, precedence_basis:"etc-eval-rubric-v0.1", confidence, arbitration_needed }`.
    `arbitration_needed = true` when confidence < 0.6 OR any judgment dimension is null OR mechanical and
    judgment verdicts disagree (fail-closed — the oneshot α/β stand-in).
  - Write the record to `the etcDecisions dir/<id>.json`, then VALIDATE it by calling
    `scripts/contracts/validate-artifact.js` on the file; if validation exits non-zero, the eval itself
    FAILS (exit non-zero) — a record that doesn't satisfy contract v0.1 is a build defect.
  - CLI: `node scripts/etc/eval.js <target> [--pack <id>] [--consult]` → prints `{decision, confidence,
    arbitration_needed, record_path}`; exit 0 on accept, 0 on revise, non-zero ONLY on internal error /
    invalid emitted record (the decision itself is data, not the process exit).

### 3. Schemas + fixture
- `schemas/etc/eval-pack.schema.json` (draft-07). Eval-pack shape (STRUCTURED — anti-CoT):
  ```
  { id, target, procedures:[string], rubric:[{dimension, weight(>0), criteria, mechanical(bool),
    checks:[{kind, value}] }], examples:[{input, expected_properties:[string]}],
    counterexamples:[{input, must_not:[string], why}] }
  ```
  Required: id, target, rubric (≥1 dimension). `checks[].kind` enum = the 6 karpathy check kinds.
- One real fixture eval-pack: `.claude/project/etc/eval-packs/etc-author.example.json` — an eval-pack that
  evaluates the `/etc:author` skill itself (dogfood). Must validate against the schema and drive the test.

### 4. Enforcer (fail-closed — the named approver per "every policy needs an enforcer")
- `scripts/checks/etc-harness-scan.js` — exit 1 (reject, not lint) when ANY:

  - any `.claude/commands/etc/*.md` lacks the standard frontmatter `description` or a `## Procedure`
    section (= invented/!standard authoring format);

  - any decision_record under `the etcDecisions dir` fails `validate-artifact.js`.
  - exit 2 on internal error (fail-closed, never silent-pass). Print a one-line PASS summary on success.
- Add it to the testsuite so `node scripts/testsuite/enforce.js` runs it (match how
