## The deep root cause: **contractless productization**

WarpOS has **no hard boundary between authoring state and the shipped runtime
contract.** The same `.claude/` + `scripts/` tree is, at once, the framework's source,
its test bed, its release artifact, and the only fully-exercised "install." That collapse
is the generator; every gap class is a symptom:

| Symptom class | Why it falls out of the collapse |
|---|---|
| Fresh-install partial wiring (sprint subsystem, templates, resume loops) | The *consumer contract* (what a clean install receives + can do) is never run; canonical passes because its state is hand-maintained and every feature already exercised. |
| "Downstream always missing" (bootstrap/canon scripts not shipped) | Authoring tree ≠ shipped snapshot; two manifests regenerated by different hands, at different times, drift. |
| Version drift *inside* canonical (0.5.0 / 0.6.1 / 0.10.0) | No single authoritative version source; nothing exercised the quorum until a real merge. |
| Guards fire in the wrong repo-role (purity blocks product commits; requirements gate blocks canonical merges) | Repo-role is inferred from "path vibes," not supplied as a first-class execution-context input. |
| Fail-open / narrate-don't-verify (silent hooks, "scaffolded" empty bundles, false-green smoke, phantom gauntlet) | No **typed success semantics** — "green" doesn't mean "the thing happened + telemetry exists." Failures are invisible in the one env that's fully set up. |
| Purge/revive churn (the `warp:flag` collision) | Retirement is encoded in a guard's relic list, not a real **lifecycle registry** with scope + rationale that both humans and guards consult. |

**Unifying statement (GPT-5.5):** *"The shipped consumer contract is not real until a
customer discovers it."* The four WARPOS.md registers ARE the missing consumer
integration test — executed by hand, four times, by four product builds.

## The one highest-leverage systemic fix: **artifact-first, contract-tested releases**

Not merely "add a clean-room sim" (a detector that rots into ritual if it installs from
the source tree). Instead:

1. **One bill-of-materials, one version source, one repo-role model.** Collapse the
   two-manifest split; make `version.json` the sole authority; make repo-role an explicit
   input every guard consults (a shared `repo-role.js`), never inferred from paths.
2. **Sealed capsule.** Every release builds one sealed install capsule from that BOM.
3. **Executable consumer contract as the release gate.** Install *only that capsule* into
   a disposable out-of-tree product repo and run: `setup → check:install → a real sprint →
   provider dispatch (assert telemetry) → update → guard behavior under BOTH canonical and
   product roles`. Ship only if it passes. It must consume the EXACT artifact downstream
   receives — otherwise you test the workshop, not the product.
4. **Typed success semantics.** "green" = "the action occurred + a telemetry record
   exists" (the `gauntlet-verify.js` / per-role-smoke pattern, generalized).
5. **Lifecycle registry.** Retired capabilities live in a real registry (scope + rationale
   + forward path) that guards read — so purge/revive is governed, not litigated per guard.

**Cheapest leading indicator (do this first):** on every commit, build the shipping
capsule and run a fresh-install smoke — *"can an empty repo receive the current shipped
manifest and complete `setup → check:install` without consulting canonical-only state?"*
If it fails, the framework is already lying about what it ships.
