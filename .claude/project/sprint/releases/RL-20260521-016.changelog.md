## Summary

WarpOS becomes the command console for a portfolio of products. The existing `/product:*` family collapses into a unified `/portfolio:*` namespace, every portfolio operation is one verb away from any WarpOS terminal, and `/portfolio:open <slug> --spawn` opens a fresh Claude Code session in a separate terminal so multiple products can run side-by-side without ever leaving WarpOS as the home base.

## New skills (12)

| Skill | Purpose |
|---|---|
| `/portfolio:list` | Print a summary table of every registered product. |
| `/portfolio:register <slug> <path>` | Add an existing local repo to the registry. Idempotent. |
| `/portfolio:open <slug> [--spawn]` | Print cd hint, or `--spawn` opens a new terminal window in the product. Active-CWD warning when target = current dir. PATH-fallback emits a copyable line. |
| `/portfolio:new <slug>` | Scaffold a fresh private sibling repo, `git init`, `/warp:setup`, register, and **auto-execute** `gh repo create --private --source=. --remote=origin --push`. |
| `/portfolio:adopt <slug>` | Promote an existing `_docs/briefs/<slug>/` or `_docs/clones/<slug>/` into a private sibling repo via `/portfolio:new --from-brief`. |
| `/portfolio:status` | Per-product dashboard: WarpOS version, last commit, dirty count, current sprint, GitHub remote. Parallel probes with 5s per-product timeout. |
| `/portfolio:dispatch <slug> /<skill> [args]` | Run any skill against a registered product's working tree by spawning a fresh `claude -p` subprocess with `CLAUDE_PROJECT_DIR=<repo_path>`. Never retargets the current session. Metacharacter input gate. |
| `/portfolio:sync` | Sequential `/warp:update` across every registered product. No fail-fast; summary table at end. |
| `/portfolio:bootstrap` | (renamed from `/product:bootstrap`) Guided brief generation. |
| `/portfolio:clone` | (renamed from `/product:clone`) Competitor-product intel. |

## Deprecations

The following `/product:*` skills are now thin deprecation aliases that forward to their `/portfolio:*` counterpart and emit a once-per-session deprecation banner:

- `/product:bootstrap` → `/portfolio:bootstrap`
- `/product:clone` → `/portfolio:clone`
- `/product:ponder` → `/portfolio:ponder`
- `/product:import` → `/portfolio:import`

Aliases live **two releases**. Removal target: **v0.10**. After that, the `.claude/commands/product/` directory and the `scripts/product/{bootstrap,clone,import}.js` re-export shims are deleted.

## Registry

A new portfolio registry document at `~/.warpos/portfolio.json` (HOME-dir, not project-local) records every product across the user's portfolio. Schema: `warpos/portfolio-registry/v1` at `schemas/portfolio/registry.schema.json`. Atomic save via temp-file + rename. Override path with `WARPOS_PORTFOLIO_REGISTRY=<path>` for tests.

## Migration plan

1. **Existing callers of `/product:*`** keep working — the deprecation alias forwards to the renamed skill and emits a banner once per session.
2. **External documentation / scripts** referencing `/product:*` should switch to `/portfolio:*` at their own pace. The 2-release window (until v0.10) gives 30–60 days of overlap.
3. **No data migration needed.** Registry is new; existing `_docs/briefs/` and `_docs/clones/` directories remain at their current location until the operator runs `/portfolio:adopt <slug>` to promote them.

## Rollback plan

1. Revert the SP-20260521-001 commit on canonical `main`. `git revert <sha>` is sufficient — every change is a single-file edit, additive script, or additive skill.
2. The `/product:*` deprecation aliases remain functional because the canonical scripts they re-export still resolve.
3. Any sibling repos the operator created via `/portfolio:new` are independent GitHub repos and are unaffected by a WarpOS rollback.
