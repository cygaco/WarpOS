# /sprint:full — autonomous sprint orchestrator (sprint-full-v1)

**Sprint:** SP-20260518-001
**Release id:** RL-20260518-010
**Target:** internal-canary (committed locally; canonical promotion + push is a separate /warp:release)

## What ships

Single-invocation execution of the full sprint pipeline
(`plan → design → execute → release-prep → retro`) under a **bounded
autonomy preset**. Cannot bypass CLAUDE.md hard ceilings.

### New skill

- `/sprint:full "<request>" [--autonomy …] [--scope …] [--sprint …]`
  — autonomous front door to the sprint pipeline. Per-phase commands
  (`/sprint:plan`, `/sprint:design`, etc.) remain available unchanged.

### Three default presets

| Preset | Pre-authorizes | Repeated failure | Branch protection |
|---|---|---|---|
| `conservative` | no_approval_needed only | halt | refuses on main |
| `moderate` (default) | + design_approval_required | **defer** | refuses on main |
| `aggressive` | + execution_approval_required, + release_approval_required (staging/internal/dev) | **defer** | `--allow-main` honored |

### Five hard ceilings (never bypassable)

1. `push_to_remote`
2. `paid_service_signup`
3. `production_deploy`
4. `destructive_migration`
5. `secret_to_remote`

Plus `FORBIDDEN_PRE_AUTH` rejects `production_release_approval` and
`paid_service_approval` at preset-load time.

## Bootstrap caveat

`/sprint:full` was built using the per-phase commands (it was the
subject of the build). Future sprints can use `/sprint:full` itself.
The first real `/sprint:full` invocation will be the live smoke test
for the orchestrator.

## Known v0.1 caveats

1. Phase 3 (execute) hands off Ralph loops to the skill body. The
   orchestrator does NOT yet drive 9-stop-reason mapping by directly
   invoking `execute.js phase` calls — the skill body is authoritative
   for stop-reason handling.
2. Phase-boundary Beta consultation event fires from the orchestrator,
   but the actual `SendMessage` dispatch is the skill body's
   responsibility (Beta is an interactive primitive).
3. Cost-estimate counter is coarse; calibrate from real telemetry
   over the first 10 runs.
4. No automated regression for the per-phase helpers themselves
   (`plan.js`, `design.js`, etc.) — we rely on existing test coverage.
