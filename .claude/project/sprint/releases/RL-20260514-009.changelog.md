# RL-20260514-009 — Sprint Routing Enforcement

**Sprint:** SP-20260514-002 · **Target:** canonical-warpos · **Version:** `warpos-sprint-routing-enforcement-v1` · **Risk:** medium

## Summary

The sprint routing policy at `paths.sprintRouting` is no longer aspirational. Every sprint artifact (Plan Contract, design pack, executed ticket, QA report, Redteam report, release record, retrospective) now carries a durable routing-trace row recording which `model_class` actually drafted it and (where required) which second-vendor model diff-reviewed it. A new PreToolUse Edit|Write hook surfaces drift at write-time during the soft-rollout window; `/sprint:release` refuses to proceed when required-phase traces are missing.

Verified end-to-end against this very sprint: `node scripts/sprint/routing.js coverage --sprint SP-20260514-002` exits 0 with 6/6 required phases covered.

## What changed (R-1 through R-14)

### R-1, R-2 — CLI surface + trace schema

- **New `routing.js record` subcommand**: validates model belongs to declared class for the phase; appends a schema-validated row to `.claude/project/sprint/decisions/routing-trace.jsonl`.
- **New `routing.js check` subcommand**: exits 0 when a matching trace row exists for `(phase, artifact, sprint)`; exit 1 with fix-up message otherwise.
- **New `routing.js coverage` subcommand**: per-phase coverage report (text and `--format json`); exits non-zero when required phases are missing.
- **New `schemas/sprint/routing-trace.schema.json`** (`warpos/sprint/routing-trace/v1`): required fields `schema, sprint_id, phase, artifact_id, model, recorded_at, recorded_by, evidence`. Validated by `routing.js record` before write.

### R-3, R-4 — Class validation + single-vendor fallback

- `record` rejects models not declared in the phase's `model_class`. Fix-up message names the policy key to edit.
- When `diff_review: true` and only one vendor is configured: `--allow-single-vendor` flag (CLI) / `allow_single_vendor: true` (programmatic) auto-degrades evidence to `single_vendor_session` and appends a row to `paths.decisionLedger`. Single-vendor users are never hard-blocked.
- `auto_override: true` (programmatic) handles the inverse case: when the recording model is in a STRONGER class than the phase declares (e.g. opus in `execution`/`economical_coder`), the row is recorded with `evidence: mismatch_override` plus an auto decision-ledger ref.

### R-5..R-9 — Sprint script wiring

- `scripts/sprint/plan.js` records `phase=planning` after `writePlanContract`.
- `scripts/sprint/design.js` records `phase=design` after rendering the requirements bundle.
- `scripts/sprint/execute.js` records `phase=execution` on Ralph `stop --reason completed`.
- `scripts/sprint/release.js cmdPrepare` records `phase=release` BEFORE the coverage gate in `cmdCheck` runs (fixes chicken-and-egg). `cmdCheck` calls `coverageReport()` and exits non-zero when required phases lack traces; `--allow-routing-gap` escape hatch logs to decision-ledger and proceeds.
- `scripts/sprint/retrospective.js` records `phase=retrospective` after `retro.yaml` is written.
- All five integrations are wrapped in try/catch and emit stderr only on failure — they NEVER block their host script.

### R-10, R-13, R-14 — Guard hook

- **New `scripts/hooks/sprint-routing-guard.js`** (PreToolUse Edit|Write):
  - Classifies sprint artifact paths: `requirements/<SP-id>/*.md` (design), `history/<SP-id>/retro.yaml` (retrospective), `releases/<RL-id>.yaml` (release; sprint id parsed from file content).
  - Fast-exits (no policy load, no trace read) when `file_path` is outside `paths.sprintRoot`.
  - Exempts sprints with status `closed`, `abandoned`, or `retrospected` from enforcement (no retroactive backfill required).
  - Fail-open when `paths.sprintRouting` is missing — preserves the "delete to disable" affordance the policy file documents.
  - Honors `enforcement.mode`: `warn` writes to stderr and allows; `block` emits `decision: block` JSON.

### R-11 — Soft-rollout policy field

- `sprint-routing.json#enforcement` block added: `{ mode: "warn", rolled_out_at: "2026-05-14T21:00:00Z", soft_rollout_until: "2026-05-21T21:00:00Z" }`.
- `routing.js validate` validates the mode is one of `warn | block`.

## Migration plan

None required. The new policy field is additive; the new trace JSONL is new file. The new guard runs in `warn` mode for the first week — operators see warnings but writes always proceed. Single-vendor sessions are not affected (fallback path).

## Rollback plan

- **Quick:** keep `sprint-routing.json#enforcement.mode = "warn"` (the default). No writes are blocked.
- **Disable hook:** remove the `sprint-routing-guard.js` entry from `.claude/settings.json` PreToolUse Edit|Write chain.
- **Disable enforcement entirely:** delete `paths.sprintRouting` (documented affordance — the guard fails open).
- **Full revert:** `git revert` the release commit. Trace data on disk is harmless and need not be cleaned.

## Monitoring after release

- **`sprint.routing.guard_warned`** — count per day. Expect non-zero during soft-rollout as operators hand-edit sprint artifacts; should converge as sprint scripts handle recording inline.
- **`sprint.routing.recorded`** — every sprint command should emit at least once. Absence in events log for an active sprint indicates a wiring regression.
- **`single_vendor_session` evidence count** — should match the number of single-vendor sessions actively running. Non-trivial growth indicates either many single-vendor users (expected) or operators bypassing diff-review (regression — A-6 in redteam plan).
- **Day 8 (2026-05-22):** review smoke confidence and flip `enforcement.mode` to `"block"` if traces are landing reliably.
