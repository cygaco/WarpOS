# RL-20260514-008 — WarpOS 0.7.0 — Hardened update pipeline

**Sprint:** SP-20260514-001 · **Target:** production · **Version:** `0.7.0` (minor bump) · **Risk:** medium

## Summary

Architectural fixes to the WarpOS `/warp:update` pipeline prescribed by the 2026-05-13 GPT-5.5 review. Closes the systemic Windows brittleness (autocrlf=true MERGE_CONFLICT false-positives) at the source. Five of six items shipped; item 4 (release/apply pipeline separation) deferred per recommended scope.

Operators on Windows can run `/warp:update --apply` on any consumer in <60s without manual file shuffling or `--skip-preflight`.

## What changed (R-1 through R-7)

### R-1 — Hash semantics + back-compat

- **New `scripts/warpos/lib/content-hash.js`**: single content-hash surface exporting `contentHash` (LF-normalized for text), `rawHash` (raw for binary), `hashMatches` (prefix-tolerant), `isTextAsset` (extension allowlist). Built-in `--selftest` (22 assertions).
- **Five callsites refactored**: `scripts/warpos/update.js`, `release-build.js`, `snapshot-installed.js`, `scripts/checks/warpos-manifest-honesty.js`, `scripts/generate-framework-manifest.js`. Inline `createHash('sha256')` / `sha256File` replaced.
- **Capsule manifest sha256 un-truncated** (T-070): `generate-framework-manifest.js` emits full 64-char sha256 per asset. The `.slice(0, 12)` is gone.
- **Consumer installedHash un-truncated** (T-071): `framework-installed.json#assets[].installedHash` is full 64-char going forward. Pre-0.7.0 12-char prefix capsules remain readable via `hashMatches`.

### R-2 — Preflight override contract

- `scripts/warpos/preflight.js` accepts `--operator-override <gate-name>` (repeatable) + `--override-reason "<text>"` (required, 8-500 chars trimmed).
- Unknown gate names rejected with the full valid gate list.
- Every accepted override emits `warpos.update.operator-override-used` to `paths.eventsFile`.
- Legacy narrow flags (`--allow-stale`, `--force-fresh`, `--allow-version-drift`) retained for back-compat; do NOT emit the new audit event. `--skip-preflight` superseded.
- JSONL injection on `--override-reason` is structurally prevented via `JSON.stringify` in the envelope writer.

### R-3 — Asset ownership state machine

- `framework/paths.registry.json` `_field_meaning.owner` documents `framework_template` and `project_owned`.
- `update.js` classifier:
  - `framework_template` + consumer non-whitespace edit → transition to `project_owned`, emit `ownership-transitioned`, classify as `LOCAL_CUSTOMIZED`.
  - `framework_template` + no edit → falls through to normal framework flow.
  - Capsule-removed `framework_template` / `project_owned` paths → `DELETE_SAFE` (preserved), never `DELETE_CONFLICT`.
- **Decision (logged to decision-ledger 2026-05-14):** automatic on any non-whitespace edit. Reversible by future sprint via decisions ledger flip.

### R-4 — Migration loader contract

- `generate-framework-manifest.js` excludes `migrations/` from `assets[]`. Migrations are referenced via the capsule's `release.json#migrations[]` only and loaded by `scripts/warpos/migrations-loader.js`.
- `scripts/checks/warpos-applied-migrations.js` is capsule-aware: fails closed only when a migration dir is on disk AND target ≤ installed AND NOT in any capsule's migration list. Stops the `copy → flag stale → delete → re-copy` loop.

### R-5 — Update events schema

Three new event kinds via `scripts/warpos/lib/update-events.js`:

- `warpos.update.content-hash-mismatch` — `kind: lf_only | real_drift`.
- `warpos.update.operator-override-used` — gate, reason, operator, ts, txId, gateStatusBefore.
- `warpos.update.ownership-transitioned` — file, from, to, reason.

### R-6 / R-7 — Replay bench + docs

- **`scripts/warpos/replay-bench.js`** (new): single driver. **9/9 pass** covering content-hash selftest, capsule un-truncation, consumer un-truncation, back-compat prefix matching, manifest-honesty post-refactor, capsule-aware applied-migrations, three preflight CLI rejection paths.
- **`scripts/warpos/test-hash-back-compat.js`** (new): verifies `hashMatches` accepts simulated 12-char prefix across all 549 framework assets.
- **`_docs/sprint/UPDATE_PIPELINE.md`** (new): three-phase pipeline map + hash semantics + ownership state machine + event surface + opt-in recovery tools.
- **`_docs/sprint/CRASH_RECOVERY.md`** updated: `/warp:update` recovery section + new event kinds + opt-in recovery tools (lf-normalize-target.js, prune-installed-assets.js).

## Migration plan

This release IS the migration: any 0.6.x consumer running `/warp:update --to 0.7.0 --apply` upgrades the back-compat read path naturally. The 12-char prefix capsules they were updated from continue to read correctly; new applies write the full 64-char hash to `framework-installed.json` going forward.

No DB. No external state to migrate.

## Rollback plan

- **Canonical (this repo):** `git revert` the release commit + delete the `warpos@0.7.0` tag if pushed. The transactional wrapper for past consumer apply runs is unaffected.
- **Consumer side:** the transaction wrapper in `scripts/warpos/transaction.js` captures a pre-apply snapshot. If a consumer reports trouble post-apply, they can `git restore .claude/framework-installed.json` and re-run a prior version's `/warp:update`. No irreversible side effects.

## Monitoring after release

- **`warpos.update.content-hash-mismatch` with `kind: lf_only`** — count after each consumer upgrade. Should converge to 0 once on 0.7.0. Non-zero indicates a caller bypassing content-hash.
- **`warpos.update.operator-override-used`** — should be 0 in steady state. Any non-zero count names the specific gate the operator hit; review whether the gate needs adjustment.
- **`warpos.update.ownership-transitioned`** — spot-check on first 0.7.0 apply against `aiweb` and `jobhunter-app`. Confirm every transition was intentional (no surprise auto-promotions).
- **Consumer dry-run first** (Beta recommendation): exercise `/warp:update --to 0.7.0 --dry-run` against `aiweb` and `jobhunter-app` before any `--apply`.
