# RL-20260514-007 — Turbo as mode argument

**Sprint:** SP-20260513-006 · **Target:** internal · **Version label:** `framework-doc-update-2026-05-14` · **Risk:** low

## What changed

Documentation-only update to the mode skills (`/mode:solo`, `/mode:adhoc`, `/mode:oneshot`) and `/turbo`. No runtime code change.

- **New `--turbo` argument** on all three mode skills. `/mode:<mode> --turbo [--scope <csv>|all] [--ttl <duration>] [--reason "<text>"]` enters the mode AND applies a turbo authorization in one command. Behavior without `--turbo` is unchanged.
- **Per-mode default scopes** (Class-B decision, logged to `paths.decisionLedger` 2026-05-14):
  - `/mode:solo --turbo` → `manifest-edit,write-jsonl` @ 60m
  - `/mode:adhoc --turbo` → `manifest-edit,write-jsonl,node-e-fs,worktree-ops` @ 60m
  - `/mode:oneshot --turbo` → `manifest-edit,write-jsonl,node-e-fs,worktree-ops` @ 4h
  - **Never** `push-to-main` or `destructive-git` in any default. Safety floor in `scripts/turbo/apply.js` + `authorization-gate.js` is unchanged.
- **Recovery section** in each mode skill body: documents both the `mode-set ok + turbo apply failed` case AND the `turbo already active` overwrite behaviour (per `apply.js` semantics).
- **Sibling note** in `/turbo.md`: "Also invoked by `/mode:<solo|adhoc|oneshot>` when `--turbo` is passed."
