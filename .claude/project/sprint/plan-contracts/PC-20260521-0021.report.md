## Interpreted Intent

Two architectural decisions on top of the original portfolio-console ask: (1) UNIFY the existing /product:* (bootstrap, clone, ponder, import) and the proposed /products:* into a single /portfolio:* namespace — rename in place, ship deprecated /product:* aliases for 1-2 releases; (2) FIRST-CLASS multi-terminal parallelism — /portfolio:open <slug> --spawn opens a fresh terminal window with Claude Code running in the target product, so the user can keep WarpOS as the home base while each active product runs in its own session. Parallel sessions are inherently safe because each product has its own .claude/ (per FRAMEWORK_VS_DOWNSTREAM.md). Combined: one unified namespace, one home-base terminal, N parallel product terminals on demand.

## Desired Outcome

User has ONE namespace (/portfolio:*) for every product-related action — no /product vs /products confusion, no awkward seam skill. User can sit in their WarpOS home-base terminal and type /portfolio:status to see the whole portfolio, /portfolio:open dreamteams --spawn to launch a fresh Claude Code session in dreamteams in a new window (then keep working in WarpOS), and /portfolio:bootstrap newthing to interview, brief, scaffold, and register a brand-new private product in one shot. Multiple products run in parallel — each terminal is its own Claude session, each repo its own state, zero collision.
