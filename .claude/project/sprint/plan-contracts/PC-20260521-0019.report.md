## Interpreted Intent

Establish the WarpOS portfolio model so DreamTeams (and future products) live as sibling repos that consume WarpOS as an installed framework via the existing framework-installed.json + scripts/warpos/update.js pipeline. Add a portfolio manifest (.claude/portfolio/manifest.yaml) that tracks each product's framework version, active lanes, validator-required flag, and last release. Ship /portfolio:list, /portfolio:sync, /portfolio:status skills as the read/write surface. Do NOT pull DreamTeams source into WarpOS yet — that's the expanded variant, which we explicitly defer pending the DreamTeams MVP week-7 r/vibecoding survey (validates the multi-runtime portability thesis before workspace-level coupling).

## Desired Outcome

WarpOS can stage DreamTeams (and future products) without inventing new coordination infrastructure. The validation primitives that WarpOS already ships (the seven adhoc agents) become the canonical Quality Gate primitives that DreamTeams references in dreamteams/team-spec/v1. Portfolio-wide visibility (which product is on which framework version, which products run validator-required) is achievable from one command in WarpOS without each product re-vendoring tooling.

## Current Behavior

- Evidence level: `verified_from_repo`
- WarpOS ships as a single canonical repo with no portfolio concept. Products built ON WarpOS (DreamTeams is the first) currently exist only as briefs under _docs/briefs/<slug>/. There is no manifest tracking which products consume the framework, no /portfolio:* skills, and no path-registry entries for portfolio state. scripts/warpos/update.js + framework-installed.json work per-product-repo but are unaware of sibling products.

## Desired Behavior

After this sprint ships: (a) DreamTeams is listed in .claude/portfolio/manifest.yaml with its repo path, current framework version, validator-required=true, and last release reference; (b) /portfolio:list emits a one-line-per-product summary; (c) /portfolio:sync iterates the manifest in parallel and dispatches scripts/warpos/update.js into each product worktree (no-op if already current); (d) /portfolio:status aggregates RELEASES.md + .session-checkpoint.json across listed products; (e) portfolio-manifest + portfolio-index keys are registered (aspirational; never landed — the actual registry lives at `~/.warpos/portfolio.json` which is user-home, not project-relative, so no registry token applies). Variant 3 (workspace orchestrator) and the Gap-Finder / Code-Stealer agent are explicit non-goals for this sprint.

### Variants

- **Minimal safe:** Index only. .claude/portfolio/index.json with {slug, repo_url, runtime, stage, last_seen} per product, plus /portfolio:list skill that reads it. Zero cross-repo writes, zero hooks reaching across boundaries. WarpOS stays tooling-focused; each product is fully independent.
- **Recommended:** Side-by-side repos with manifest. WarpOS is the substrate (framework). Products are sibling repos consuming WarpOS via existing scripts/warpos/update.js + framework-installed.json. .claude/portfolio/manifest.yaml tracks framework_version per product. /portfolio:list, /portfolio:sync (parallel update across product repos), /portfolio:status (aggregates RELEASES.md + checkpoints). Validation-primitive agents distribute via framework install — DreamTeams team-spec/v1 references them as Quality Gate primitives. Owns: framework versioning, validation-primitive distribution, portfolio-wide release cadence. Does not own: product code, product-specific agents, product business logic.
- **Expanded:** Full workspace orchestrator with skill suite. WarpOS becomes a monorepo workspace hosting all products as packages (products/<slug>/). One .claude/, one paths registry, one event log; cross-product agents call in-process. WarpOS Alpha orchestrates across product boundaries. New skill suite: /portfolio:bootstrap, /portfolio:promote-feature, /portfolio:harvest-pattern, /portfolio:gap-find (Gap-Finder agent from DreamTeams v0.2 vision lives here naturally). Cross-product telemetry → single events.jsonl, single learnings store. Single release cadence covers all products.
