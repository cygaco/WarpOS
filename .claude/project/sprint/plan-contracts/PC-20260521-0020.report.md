## Interpreted Intent

Formalize the polyrepo workspace pattern that already exists on disk into a first-class WarpOS capability: a portfolio registry of products (each its own private repo), a /products:* skill family that can list, register, scaffold, dispatch-into, and report status across the whole portfolio, plus a privacy boundary that keeps product-specific artifacts (briefs, clones, runtime state) out of canonical WarpOS public history. Two specific in-flight artifacts must migrate: _docs/briefs/dreamteams/ (real product to build) and _docs/clones/companycam/ (competitive intel) — neither has been committed/pushed yet, so the migration is purely forward-looking.

## Desired Outcome

Single command console from which the user (and their team collaborators) build, ship, and operate every product. The user types /products:open dreamteams and is dropped into that product's working tree with WarpOS skills available; types /products:status and sees every product's WarpOS version, last commit, open sprint, and CI state at a glance; types /products:new <slug> --from-brief dreamteams and gets a fresh private sibling repo scaffolded from the existing brief. Products stay private to GitHub but git-backed-up; WarpOS stays public framework.

## Desired Behavior

WarpOS canonical exposes a /products:* skill family backed by a HOME-dir registry (~/.warpos/products.json) that lists every product the user manages, its on-disk path, its GitHub remote, its WarpOS version, and its current sprint state. The user can list, open, scaffold, dispatch-into, and report on the portfolio from inside WarpOS. Product-specific artifacts (briefs, clones, runtime state, sprint trackers) are gitignored in canonical WarpOS and live instead under each product's private sibling repo. /products:new <slug> scaffolds a new private sibling (gh repo create --private gated behind --create-remote; off by default). Existing /warp:* skills continue to work but learn to read the portfolio registry instead of walking the parent directory. Migration: dreamteams + companycam briefs move from _docs/briefs/clones inside canonical into their own private sibling repos.

### Variants

- **Minimal safe:** Registry-only. Add `~/.warpos/products.json` (user-home; not project-relative so no registry token applies — the `productsRegistry`/`productsHome` keys were aspirational and never landed), gitignore _docs/briefs/ and _docs/clones/ in canonical. Ship 3 skills: /products:list, /products:register, /products:open. User creates the private GitHub repos manually; the skill just records what's where on disk. Migrate dreamteams + companycam briefs by hand into freshly-created private sibling repos. No automation around scaffolding, dispatch, or status reporting.
- **Recommended:** Workspace orchestrator. Minimal_safe PLUS: /products:new <slug> (scaffolds sibling repo, runs /warp:setup; optional --create-remote calls gh repo create --private), /products:from-brief <slug> (migrates an existing _docs/briefs/<slug> or _docs/clones/<slug> into a new sibling), /products:status (portfolio dashboard: WarpOS version, last commit, sprint state, open PRs), /products:dispatch <slug> <skill> (run any skill against a sibling product's working tree without cd-ing), /products:sync (pull every product to latest WarpOS in one pass). The command-console framing is delivered. Migration of dreamteams + companycam goes through /products:from-brief as the dogfooded first use.
- **Expanded:** Portfolio operating system. Recommended PLUS: cross-product memory (~/.warpos/portfolio/memory/ — shared learnings ranked across the portfolio), /sprint:portfolio (single dashboard of every active sprint across every product), per-product agent overrides (each product can pin/customize agents while inheriting canonical defaults), encrypted backup of per-product runtime state (events.jsonl, learnings.jsonl, traces.jsonl) to a private cloud target, team-collaborator metadata (registry tracks GitHub access, surfaces in /products:status). Aimed at the moment where there are 10+ products and a team of 3+ collaborators.
