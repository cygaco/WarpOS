> # Extending the `product` skill suite

## Product Cloning

/sprint:plan --turbo a `product:clone` skill that intakes information about a product, explores the product, and creates high-level requirements that can be used to clone it.

### Information Sources

Possible information sources are:
1. Videos about the product
2. Website for the product
3. Reviews and adjacent information for the product
4. Other types of sources along these lines

### Product Exploration Requirements

Ensure that the following are included in your product exploration:
1. If watching a video about a product, and you do not have a name for it, find the name and search the web about it (including its own website)
2. If browsing a product's website, discover links to crawl and find them.
3. Attempt to find reviews.

### Deliverables

The skill should deliver:
1. JTBDs of their Product
2. Feature list, with complexity to build and how 'core' a feature is to their Product
3. What their users say about it
4. Gaps in their Product
5. Opportunities we can capitalize on

### Goal

The goal of this skill is to enable me to rapidly deploy clones or competing products to companies that I want to kill.

## Product Mining

/sprint:plan --turbo a skill that basically spits out questions for another claude session in another project to answer about the product being built.

Make sure it works for claude code, codex, claude (just normal app), chatgpt (just normal app), etc

It should basically be a pre-step to the product:bootstrap skill

It should be called `product:convert`

### Goal

Convert a product from being trapped in a simpler type of project to a claude code project, with enough context to run `product:bootstrap` and create requirements for existing features.

[follow-up message from user: Actually instead of 'product:convert' make it 'product:import']

## Interpreted Intent

Create a new skill /product:import in .claude/commands/product/ that, run in the target project, inspects local context (PROJECT.md, README, package.json, last N commits) and emits a single paste-friendly Markdown questionnaire artifact at _docs/imports/<slug>/<slug>.questionnaire.md. The questionnaire is structured to be paste-compatible across five target surfaces: Claude Code, Codex, Claude web app, ChatGPT web app, Gemini web app. Sections mirror /product:bootstrap's section set so answers can be brought back and consumed by /product:bootstrap --answers-file. User renamed the skill from /product:convert to /product:import mid-prompt — final name is import.

## Desired Outcome

Operator can rescue a product 'trapped' in a simpler project (older repo, ChatGPT thread, scattered notes) and convert it into a proper Claude Code project with enough context that /product:bootstrap can create real requirements for features that already exist. Removes the manual interview burden when the source-of-truth lives in another session or tool.

## Current Behavior

- Evidence level: `verified_from_repo`
- /product:bootstrap exists and runs an interactive 4-8-question conversation, writes _docs/briefs/<slug>/<slug>.brief.{md,html,docx}. It accepts --answers-file <path> with JSON keyed by section id. There is no skill that generates a paste-friendly questionnaire for another session. An operator wanting to use bootstrap with an answer file currently has to construct the JSON manually.

## Desired Behavior

Operator runs `/product:import` in the project where they want the brief to land. The skill: (a) inspects the project (any existing PROJECT.md, README, package.json, last ~10 commits) bounded read-only for hints; (b) emits a single Markdown questionnaire at _docs/imports/<slug>/<slug>.questionnaire.md containing project-context preamble, one section per /product:bootstrap section (problem, JTBD, value chain, ...), paste-friendly question prompts, and an explicit response-format instruction for the answering session; (c) renders identically enough across Claude Code, Codex, Claude web, ChatGPT web, and Gemini web that it works in all five. Operator pastes into another session, gets answers back, runs `/product:bootstrap --answers-file _docs/imports/<slug>/<slug>.answers.json` (or a paste-back-and-parse helper) to convert answers into a brief.

## Scope

- Size: `m`
- Risk: `low`

### Variants

- **Minimal safe:** Single questionnaire MD output, no project introspection (operator passes name only). No answer-parsing helper — operator manually constructs answers.json or pastes section-by-section.
- **Recommended:** Project introspection: read PROJECT.md, README.md, top-level package.json, last 10 commits — extract hints into preamble. Emit questionnaire MD with embedded paste-back format hint. Companion answers-parse helper: when operator pastes answers back, /product:bootstrap --answers-file is auto-callable. Aligned with /product:bootstrap minimal section set (8 sections).
- **Expanded:** Recommended + per-surface presets (--for claude-code/codex/chatgpt/gemini) with subtly tailored prompt phrasing. Per-section response-format examples. Optional --section-set extended (12 sections) matching bootstrap's extended set. Round-trip validation: import → answer → bootstrap → verify all sections drafted.
