> The routing policy for reviewers, gauntlets, etc in sprints is aspirational, not enforced. Fix that.

## Interpreted Intent

Today paths.sprintRouting declares per-phase model_class (planning, plan_contract_review, design, qa, redteam, release, retrospective, external_service_setup, …) and which phases require diff_review across two vendor rows. scripts/sprint/routing.js loads/validates the policy. But /sprint:plan, /sprint:design, /sprint:execute, /sprint:release never call routing.js, never record which model drafted an artifact, and never verify diff_review was satisfied. The skill bodies do not reference routing either. Goal: make routing observable + checkable + blocking at the artifact boundary so the policy stops being decorative.

## Desired Outcome

Every sprint artifact (Plan Contract, design pack, executed tickets, qa/redteam reports, release record, retrospective) carries a durable routing-trace row recording which model_class actually drafted it and (where required) which second-vendor model diff-reviewed it. Sprint commands cannot finalize an artifact without that trace. Violations fail with a fix-up message at write-time instead of being discovered later in retro.

## Desired Behavior

Per-phase routing-trace rows are written every time a sprint artifact is finalized. The CLI `node scripts/sprint/routing.js record …` validates that the recorded model belongs to the declared class. A guard hook blocks Edit/Write on sprint artifact paths until the matching trace row exists. `routing.js check --phase X --artifact Y` is the canonical pre-finalize verifier; `routing.js coverage --sprint <SP-id>` summarizes per-phase coverage and is called by /sprint:release as a gate. When diff_review is required and a second vendor is unavailable, `routing.js record` logs to paths.decisionLedger and emits an `evidence: "single_vendor_session"` trace row so the policy's fallback_interaction rule is preserved.

- **Recommended:** minimal_safe + a new `sprint-routing-guard.js` PreToolUse Edit|Write hook that fires when paths inside `paths.sprintRoot` matching artifact globs (Plan Contract YAML, design pack files, retro.yaml, release record YAML, ticket finalized states) are written, demanding a matching trace row in routing-trace.jsonl. Hook is fail-open with explicit `--soft-rollout` flag for the first week so the team can opt-in per artifact while we trust the rail. plan.js/design.js/execute.js/release.js/retrospective.js each gain a thin call to `routing.js record` at the moment they write their artifact. New schemas/sprint/routing-trace.schema.json codifies the trace row.
