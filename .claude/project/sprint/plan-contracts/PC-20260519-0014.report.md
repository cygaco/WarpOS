## Original Request (verbatim)

> Every sprint to be recorded in ROADMAP.md, and all releases to be recorded in RELEASES.md (include 'release notes'). Consider what counts for a release with /reasoning:run

## Interpreted Intent

Establish a durable, machine-enforceable ledger discipline so two repo-root docs become canonical entry points: ROADMAP.md must carry an entry for every sprint (closed, in-flight, planned) and RELEASES.md must carry an entry for every release event with release notes. The /reasoning:run pass already produced a two-tier policy for what counts as a release (RT-011): MUST=(version bumps, deployed/prepared RL-*), MAY=(bare git tags with capsule outside /warp:release), MUST NOT=(hotfix without RL-*, docs-only). The sprint codifies this policy into the operating loop — writers, hooks, skill checklists, scaffolds.

## Desired Outcome

Any reader (future Alex session, downstream consumer, founder) can answer 'what work has happened?' from a single file at repo root, and 'what shipped where, with what notes?' from a sibling file at repo root — without grep diving through .claude/project/sprint/. Closes the chronic LRN class 'release-capsule-gap' and 'status-transition-edge-ownership' by making the ledger a first-class artifact every release-class skill must update.

## Current Behavior

- Evidence level: `verified_from_repo`
- Sprints are recorded only in .claude/project/sprint/active-sprints.yaml + per-sprint subdir under sprints/<SP-id>/. Releases are recorded only in .claude/project/sprint/releases/RL-*.yaml + .changelog.md AND in version.json/framework/releases/. No repo-root index ties them together. ROADMAP.md exists but is framework backlog, not sprint ledger. RELEASES.md does not exist.

## Desired Behavior

Two repo-root ledgers maintained by skill+script enforcement (not by Alex memory). ROADMAP.md gains a 'Sprints' section with one row per sprint (id, title, status, started, closed, release-ref); the existing Phase backlog stays as-is below it. RELEASES.md is a new file with two sections: 'Versions' (one row per version.json bump, linked to capsule under framework/releases/, with a 1-2-sentence summary readable by downstream consumers) and 'Sprints' (one row per RL-* at status=deployed OR prepared-at-internal-canary, linked to RL-*.yaml + .changelog.md, with one-line outcome). All writes are skill-driven; manual edits remain valid (markdown).
