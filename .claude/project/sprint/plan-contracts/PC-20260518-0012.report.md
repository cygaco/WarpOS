## Interpreted Intent

Two related hygiene problems converged in the prior session. (1) scripts/hooks/format.js calls execSync('npx prettier --write ...') per Edit/Write — 2 Node cold-starts per file edit. On Windows, child cleanup is unreliable on timeout. A downstream project's session leaked enough Node processes to bog the machine. (2) The /sprint:full retro flagged that PreToolUse hooks don't validate their `updatedInput` payload shape per tool — different shape for Write vs Edit (and MultiEdit, when used) — and a payload-shape bug was the root of a real regression. Sprint B fixes the format.js spawn pattern (replace `npx prettier` with require.resolve('prettier/bin/prettier.cjs') + execFileSync(process.execPath, [bin, ...]); add ETIMEDOUT catch + taskkill /F /T /PID on Windows), adds a lint-hook-output.js PreToolUse hook that catches payload-shape mismatches at write-time, ships a /check:node-procs diagnostic skill (read-only, lists Node procs by start-time + working-set), and documents the run_in_background orphan pitfall in operational-loop.md + /sprint:execute.md.

## Desired Outcome

Developer machines stop accumulating leaked Node processes during sprint runs. Hook-payload regressions surface at write-time, not weeks later via behavior drift. Operators get a one-command diagnostic to inspect Node-process state without having to remember tasklist/ps incantations. Documentation closes the run_in_background-in-Ralph footgun that bit a downstream project this week.

## Current Behavior

- Evidence level: `verified_from_repo`
- Every Edit/Write triggers PostToolUse format.js which spawns `npx prettier --write <file>`. On Unix this is fast-ish; on Windows the npx → prettier chain is two cold Node starts and `execSync` with timeout 10000ms has no explicit child-process kill on timeout — Node sends SIGTERM (not honored by cmd.exe wrappers). Errors are swallowed by the catch-all. There is no PreToolUse hook that validates the Edit/Write `updatedInput` payload shape — hooks read `event.tool_input?.file_path || event.tool_input?.content?.file_path` defensively, but a payload-shape regression (e.g., upstream Claude Code renaming a key) only surfaces when a hook acts on undefined and a downstream effect breaks.

## Desired Behavior

format.js: replace `execSync('npx prettier ...')` with `execFileSync(process.execPath, [require.resolve('prettier/bin/prettier.cjs'), '--write', filePath])` (one Node cold-start, no shell, no `npx` indirection). Add explicit ETIMEDOUT catch; on Windows, run `taskkill /F /T /PID <pid>` to kill the child tree (the existing code has no captured PID). On non-Windows, send SIGKILL to the child PID. lint-hook-output.js: new PreToolUse hook on Edit|Write that asserts the payload-shape contract per tool — emits a one-line stderr warning + exit 0 (warn-only initially, like sprint-routing-guard's soft-rollout) when shape doesn't match expected. /check:node-procs: read-only skill prints Node procs sorted by start-time, columns: PID, started, working-set, command (truncated to 120 chars). operational-loop.md: new section explaining run_in_background semantics, orphan risk, when to use Monitor vs Bash run_in_background. /sprint:execute.md: one-line warning against `run_in_background` in Ralph test phase.
