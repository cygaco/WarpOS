## Current Behavior

- Evidence level: `verified_from_repo`
- Update pipeline assumes byte-perfect equality across LF/CRLF boundaries. On Windows (autocrlf=true), every text framework file produces a MERGE_CONFLICT false positive on first /warp:update. Capsule manifest's sha256 is truncated to 12 chars (generate-framework-manifest.js:121), propagated into framework-installed.json via update.js:490, then compared with === against full 64-char local sha — never matches. Preflight has 10 gates with override flags for only 4 (install-baseline, capsule-resolvable, version-quorum, staleness); the other 6 (manifest-honesty, path-resolution, structure-parity, applied-migrations, migration-presence, tracked-transients) have no override path. --skip-preflight exists but the code itself flags it 'NOT recommended'. Migrations ship as framework assets in capsule's framework-manifest.json#assets[]; apply copies them; applied-migrations gate flags them stale; operator deletes; next apply re-copies — infinite loop unless deleted post-apply. Consumer content placed in former-framework-template paths (e.g. _requirements/00-canonical/*.md, observed in jobhunter-app's Jobzooka project brief) gets classified DELETE_CONFLICT on framework version changes that drop the templates.

## Desired Behavior

Single /warp:update --source <canonical> --target <consumer> --to <version> --apply completes cleanly on Windows with 540+ Class A items and 0 Class C, no manual file shuffling, no --skip-preflight escape. Preflight overrides require explicit gate name + reason and emit audit log. Migrations stay in canonical only. Project content in framework template dirs survives version transitions. Capsule manifests are unambiguous about file content (full 64-char hash, single canonical comparison).
