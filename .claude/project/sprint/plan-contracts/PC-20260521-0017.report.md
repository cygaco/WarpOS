## Original Request (verbatim)

> # Extending the `product` skill suite

## Product Cloning

/sprint:plan --turbo a `product:clone` skill that intakes information about a product, explores the product, and creates high-level requirements that can be used to clone it.

### Information Sources

Possible information sources are:
1. Videos about the product
2. Website for the product
3. Reviews and adjacent information for the product
4. Other types of sources along these lines

### Product Exploration Requirements

Ensure that the following are included in your product exploration:
1. If watching a video about a product, and you do not have a name for it, find the name and search the web about it (including its own website)
2. If browsing a product's website, discover links to crawl and find them.
3. Attempt to find reviews.

### Deliverables

The skill should deliver:
1. JTBDs of their Product
2. Feature list, with complexity to build and how 'core' a feature is to their Product
3. What their users say about it
4. Gaps in their Product
5. Opportunities we can capitalize on

### Goal

The goal of this skill is to enable me to rapidly deploy clones or competing products to companies that I want to kill.

## Product Mining

/sprint:plan --turbo a skill that basically spits out questions for another claude session in another project to answer about the product being built.

Make sure it works for claude code, codex, claude (just normal app), chatgpt (just normal app), etc

It should basically be a pre-step to the product:bootstrap skill

It should be called `product:convert`

### Goal

Convert a product from being trapped in a simpler type of project to a claude code project, with enough context to run `product:bootstrap` and create requirements for existing features.

[follow-up message from user: Actually instead of 'product:convert' make it 'product:import']

## Interpreted Intent

Create a new skill /product:clone under .claude/commands/product/ that ingests intake about a competitor's product (URL, video, name) and emits a competitive-clone deliverable set under _docs/clones/<slug>/ — JTBDs, scored feature list (build-complexity S/M/L/XL + how-core 1-5), voice-of-customer with quote attribution, gaps, opportunities. Skill mirrors /product:bootstrap's generator architecture (skill spec + scripts/product/clone.js + framework/templates/product-clone/ + paths registration). Output is detailed enough to feed directly into /product:bootstrap or /sprint:plan for a competing build.

## Desired Outcome

Operator can rapidly stand up a competing or cloned product against a target company by running one skill. Output is a research-grade competitive analysis under _docs/clones/<slug>/ that immediately hands off to /product:bootstrap or /sprint:plan. Reduces 'what does this product even do' from days of manual research to one bounded skill invocation.

## Current Behavior

- Evidence level: `verified_from_repo`
- Two product:* skills exist: ponder.md (exploratory reflection) and bootstrap.md (interactive brief generator). Neither addresses competitor intel. /product:bootstrap is single-product and interviews the operator; it does not crawl external sources. There is no skill for ingesting outside product information or producing competitive analysis.

## Desired Behavior

Operator runs `/product:clone` with --name <product-name>, --url <product-url>, and/or --video <video-url>. Skill identifies the product (web-searching when only a video/name is given), discovers crawlable URLs from the product website (one level deep across pricing/docs/blog/about/features), attempts 2-3 review sources (G2, ProductHunt, Reddit, HN, Twitter, blog posts), and emits a single deliverable set under _docs/clones/<slug>/: MD always, HTML always, DOCX when pandoc is present. Deliverable contains: (1) JTBDs (3-5), (2) feature list with S/M/L/XL build-complexity + 1-5 core-ness scores, (3) voice-of-customer quotes with source URL + retrieval timestamp, (4) gaps in the product, (5) capitalize-able opportunities. Output is detailed enough that /product:bootstrap or /sprint:plan can ingest it as primary input for a competing build.

## Scope

- Size: `l`
- Risk: `medium`

### Variants

- **Minimal safe:** URL-only input. Operator manually seeds 2-3 review URLs. No video. No auto-discovery beyond one level of the supplied URL. MD-only output. ~1 skill + 1 generator + 1 template dir.
- **Recommended:** URL + name + video inputs. WebSearch enrichment when only video/name given. One-level link discovery from product site. Auto-find reviews across 2-3 sources (G2, ProductHunt, Reddit). MD + HTML always, DOCX when pandoc — matches /product:bootstrap output contract. Skill + generator + templates + paths registration.
- **Expanded:** Recommended + video transcript ingestion (yt-dlp or MCP transcript) + reviews across 5+ sources + competitive matrix CSV alongside MD + optional auto-feed to /sprint:plan for a clone build.
