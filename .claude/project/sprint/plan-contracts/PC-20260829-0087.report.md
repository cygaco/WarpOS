## Interpreted Intent

Make WarpOS's own admission gates unable to report a pass they did not verify: partition 'absent' from 'unreadable/threw' at every gate, fail closed on the latter, and prove each fix with a seeded corrupt-input fixture that RED-tests the old fail-open path. Then close the adjacent enforcement-debt rows whose shape is the same false-green family.

## Desired Outcome

A green gate means the gate checked. Today deleting or corrupting one JSON file silently disables the builder-dispatch admission gates and the only signal is a stderr WARN inside a hook whose output nobody reads — so every 'gauntlet green' claim in this framework rests on gates that cannot distinguish a pass from a failure to look.

## Desired Behavior

Every gate partitions its input into three outcomes and says which one it took: PASS (checked, satisfied) / SKIP (the checked thing is legitimately ABSENT — printed explicitly, exit 0) / FAIL-CLOSED (present-but-unreadable, parse error, runner crash, unexpected throw — non-zero exit, never silent). The partition is enforced by an audit that plants corrupt input at each registered gate and RED-tests any that exits 0, so a future gate cannot regress into fail-open without the audit failing.
