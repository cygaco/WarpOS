## Original Request (verbatim)

> If we don't already have it, a quick smoke test on warpos install and update to verify that all the models/providers work in a project, and if they don't, to do root cause analysis and fix it.

## Interpreted Intent

Wire the existing provider-health primitive into /warp:install and /warp:update lifecycles as a smoke gate; on red/yellow status, run an RCA that maps the failure status to a known root cause and applies an auto-fix when safe, else prints explicit remediation.

## Desired Outcome

After install or update the operator knows immediately whether every required provider works; failures are diagnosed (not just reported) and fixed when possible without manual troubleshooting.

## Affected Surfaces

| Surface | Evidence Level | Notes |
|---|---|---|
| scripts/warpos/provider-health-check.js | verified_from_repo | Existing CLI. Already classifies green/yellow/red and prints one-line suggestions. |

## Current Behavior

- Evidence level: `verified_from_repo`
- provider-health-check.js exists and is invoked by /warp:health and /warp:setup. It classifies green/yellow/red with one-line suggestions but does NOT run RCA or auto-fix. /warp:update has postUpdateChecks support per release.json but provider-smoke is not currently declared as one. There is no single failure-mode catalog mapping status codes to root causes + safe-fix flags.

## Desired Behavior

Smoke test runs as a terminal step of /warp:install and /warp:update (and is invokable standalone). For each red/yellow status, the framework computes an RCA: which file, env var, CLI, or registry caused it. If the cause is fixable safely (e.g., regenerate registry cache, fix env profile), apply the fix. If not safe (e.g., user must install gemini CLI), print explicit one-line remediation and exit non-zero on red.

## Scope

- Size: `m`
- Risk: `medium`

### Variants

- **Minimal safe:** Wire existing provider-health-check.js to run as final step of /warp:install and /warp:update with --json output to a runtime log. No RCA, no auto-fix. Surface green/yellow/red and exit non-zero on red.
- **Recommended:** Above + a failure-mode catalog mapping the top 5 known statuses to root causes and a `safe_to_autofix` flag. Auto-fix dispatcher runs only safe fixes; the rest print explicit remediation. Smoke runs in both install and update; failures stop the lifecycle (or rollback if Plan 5 ships transactional wrap).
- **Expanded:** Above + full self-healing layer. Every known failure mode mapped. Risky fixes prompt via AskUserQuestion. Recurring failures auto-log via /issues:log. Smoke results logged to events.jsonl with trend analysis surfaced by /check:patterns.
