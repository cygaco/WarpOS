# PRD — Consolidate ROADMAP.md and WARPOS_ROADMAP.md into single canonical ROADMAP.md (scaffold still shipped from generator)

**Sprint:** `SP-20260518-009`
**Plan Contract:** `PC-20260519-0013`
**Status:** draft
**Documentation scale:** `s`

## Outcome

One canonical roadmap file at repo root (`ROADMAP.md`) that holds the framework backlog. `WARPOS_ROADMAP.md` no longer exists. Consumer install/update behavior is unchanged: the scaffold is still produced by `scripts/warpos/generate-roadmap-scaffold.js` (which encodes the scaffold as an inline JS string, independent of canonical's `ROADMAP.md`). Live-code references to `WARPOS_ROADMAP.md` are removed; historical references in `_docs/phase0/*` and `framework/releases/0.4.0/changelog.md` are deliberately frozen.

## Context

### Original Request

> do it

### Interpreted Intent

Collapse the two-file roadmap convention (`ROADMAP.md` scaffold + `WARPOS_ROADMAP.md` framework backlog) into a single canonical `ROADMAP.md` that holds the framework backlog. The consumer-facing scaffold continues to be generated programmatically by `scripts/warpos/generate-roadmap-scaffold.js`.

### Current Behavior

Two files at canonical repo root: `ROADMAP.md` (scaffold, ~40 lines, decoration only) and `WARPOS_ROADMAP.md` (real framework backlog, ~516 lines). `scripts/warpos/promote.js` excludes both from consumer propagation. Consumers receive the scaffold only via `generate-roadmap-scaffold.js`, which uses an inline JS string and never reads canonical's `ROADMAP.md`. Net effect today: canonical's `ROADMAP.md` is unused by consumers and exists only to remind canonical-repo readers about the convention.

### Desired Behavior

Canonical repo root has exactly one `ROADMAP.md`, containing the framework backlog (current contents of `WARPOS_ROADMAP.md`). `WARPOS_ROADMAP.md` no longer exists. Consumer install/update behavior is unchanged: scaffold is still produced by `generate-roadmap-scaffold.js`. Live-code references to `WARPOS_ROADMAP.md` are removed; historical references are frozen.

## Requirements

- `R-1` — **Single canonical roadmap file.** Repo root MUST contain exactly one `ROADMAP.md`. `WARPOS_ROADMAP.md` MUST NOT exist on disk. The new `ROADMAP.md` MUST contain the framework backlog content (i.e., the prior `WARPOS_ROADMAP.md` body) with the obsolete header/footer cross-links removed and a single header HTML comment explaining its dual identity.
- `R-2` — **Live-code reference cleanup.** The string `WARPOS_ROADMAP` MUST NOT appear in any live code path under `scripts/`. Specifically, the following allowlist entries MUST be removed: `scripts/warpos/promote.js` FRAMEWORK_PREFIXES, `scripts/paths/gate.js`, `scripts/path-lint.js`. The `scripts/phase0-verify.js` checks that depend on the prior two-file convention MUST be rewritten to assert the post-consolidation invariant (`ROADMAP.md` exists AND is excluded from propagation by `promote.js`).
- `R-3` — **Historical references frozen.** Files under `_docs/phase0/*`, `framework/releases/0.4.0/changelog.md`, and `_docs/sprint/FINDINGS.md` MUST NOT be modified. They document the prior two-file convention as a historical fact and remain accurate as history.
- `R-4` — **Consumer behavior unchanged.** `promote.js --dry-run` from canonical MUST still exclude `ROADMAP.md` from propagation. `scripts/warpos/generate-roadmap-scaffold.js` MUST still write its inline scaffold to a target dir when no `ROADMAP.md` is present there.
- `R-5` — **Verification clean.** `node scripts/phase0-verify.js` MUST exit 0 after the cleanup. `grep -r WARPOS_ROADMAP scripts/` MUST return no matches.

## Non-Goals

- Splitting roadmap from changelog (the current `WARPOS_ROADMAP.md` mixes both — separate sprint).
- Refactoring the scaffold-generator script itself.
- Updating historical references in `_docs/phase0/*` or `framework/releases/0.4.0/changelog.md`.
- Shipping a consumer migration script for older installs.
- Adding a new `/check:*` skill for roadmap honesty.
- Touching `DUMP.md` (transient, regenerated by `/session:dump`).
