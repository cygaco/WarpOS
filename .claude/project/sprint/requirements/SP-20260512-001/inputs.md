# INPUTS — Multi-sprint parallelism

**Sprint:** `SP-20260512-001`
**PRD:** `prd.md`

Inputs to the sprint subsystem. WarpOS sprint has no UI forms — inputs are CLI flags, yaml fields, and skill arguments. Each entry is testable.

---

## IN-1 — `--sprint <SP-id>` flag (linked story `S-7`)

| Property | Value |
|---|---|
| Field | `--sprint <SP-id>` |
| Type | string |
| Required | no (defaults to `active-sprints.yaml#primary`) |
| Source | CLI (sprint helper invocation) |
| Validation | matches `^SP-[0-9]{8}-[0-9]{3}$` AND exists in `active-sprints.yaml` |
| Failure mode | unknown id → exit non-zero, print COPY C-10 |

**Notes:** Accepted by all 8 helpers in `scripts/sprint/`. Re-validated on every invocation (registry can change mid-session).

## IN-2 — `lane` block on Plan Contract (linked story `S-9`)

| Property | Value |
|---|---|
| Field | `plan_contract.lane` |
| Type | object `{ type, value, isolation_notes }` |
| Required | yes (defaults to `{ type: "default", value: null, isolation_notes: "" }`) |
| Source | `/sprint:plan` payload OR Plan Contract hand-edit |
| Validation | `type ∈ {default, worktree, branch}`; `value` is path-or-null; `isolation_notes` is string |
| Failure mode | schema validation fails → plan.js exits non-zero before writing |

**Notes:** Inherited by `current-sprint.yaml.lane` and read by `/sprint:execute`.

## IN-3 — `active-sprints.yaml#primary` (linked stories `S-1`, `S-6`)

| Property | Value |
|---|---|
| Field | `primary` (top-level) |
| Type | string (sprint id) |
| Required | yes — there is always exactly one primary |
| Source | written by `init.js` (first sprint) and by `/sprint:plan` (any new sprint that does not pass `--keep-primary`) |
| Validation | matches `^SP-[0-9]{8}-[0-9]{3}$` AND has an entry in the `sprints` array |
| Failure mode | primary points at a non-existent entry → `validate.js` fails; helpers print `active-sprints.yaml corrupt` |

**Notes:** The "default sprint" knob. Switched via `node scripts/sprint/init.js --set-primary <SP-id>` (added with `S-7`).

## IN-4 — `--allow-overlap` flag (linked story `S-13`)

| Property | Value |
|---|---|
| Field | `--allow-overlap` |
| Type | boolean (presence) |
| Required | no |
| Source | `/sprint:execute` or `/sprint:plan` invocation |
| Validation | presence-only |
| Failure mode | n/a — but the override is logged to the decision ledger with reason `manual_allow_overlap` so audit can see it |

**Notes:** Existence of this flag is the safety release valve. Without it, the conflict-check is a block, not a warning, at execute time.
