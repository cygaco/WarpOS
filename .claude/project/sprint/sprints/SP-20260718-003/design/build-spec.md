## THE LOAD-BEARING DECISION — D1↔D5 CLI-not-in-process
The two cross-provider labs (agy primary, gpt second_pass) MUST dispatch via CLI subprocess; an in-process Agent-tool spawn for either is a **contract violation that fails closed** (D1 makes the Agent-tool channel resolve Claude regardless of pin → in-process gpt/agy silently becomes a Claude clone = all-Claude panel masquerading as 3-lab). The claude third_pass is the ONE legal in-process lane. **Three teeth:**
1. Lane contract declares a per-lane REQUIRED shape (gpt/agy → `subprocess-cross-provider`; claude → `in-process-agent` sanctioned); the panel-manifest validator fails closed if a cross-provider lane is any other shape.
2. Attestation (D8) binds to the CLI executable return: liveness = a `dispatch-completions.jsonl` record with `tool_id∈{codex,gemini,agy}`, `shape==="subprocess-cross-provider"`, `fallback===false`, non-null `output_digest`, same-run `run_id/sprint_id`. A `record-inprocess`/provider:claude record satisfies ONLY the claude hunter — supplying it for a gpt/agy-contracted lane FAILS attestation.
3. Panel-runner precondition in `dispatch-review.js`: a required cross-provider lane not resolved to a CLI subprocess is refused before merge (reuse `attestRanOnGpt` shape-check).
