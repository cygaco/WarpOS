### Deep Read
- **What emerged:** Versions are commits, but *capsules* are rungs. The user climbed `version.json` but stepped into air where a capsule should have been. The release pipeline was building boxes (commits) without rungs (capsules), and only the box-shaped ones at the top happened to also be rungs.
- **Hidden tension:** "Released" was overloaded. Commit ≠ capsule. The release script emits both, but if either is skipped — for any reason: a hand-typed bump, a dropped step, a crash mid-pipeline — the ladder grows but the climber can't follow.
- **Subconscious learning:** Every `version.json` bump must be reachable from `/warp:update`. The audit isn't "did we tag?" — it's "can a downstream stranger get here?" That's the rung test. Carry forward as a release gate: `tag without capsule = release fail` is L-2's enforcement target.

### Deep Read
- **What emerged:** The β-gate isn't a guard, it's a doorbell that no one rang. 17 blocks doesn't mean β rejected things — it means the agent kept walking past the door. The pattern is muscle memory: solo-decide first, route through β only when prompted.
- **Hidden tension:** Either β is being asked the wrong questions (and we route around because we don't trust its scope), or the CLAUDE.md protocol is too easy to forget at the moment of action. The gate fires *after* the omission, which is too late — the decision has already crystallized in the conversation.
- **Subconscious learning:** Beta consultation has to happen at the *intent* layer, not the *action* layer. The reminder needs to be where the deliberation starts ("I'm about to choose between A and B…") not where the side-effect lands. Possibly a slash-skill `/beta:ask` that's so cheap to invoke it costs less than skipping it.

### Deep Read
- **What emerged:** "/fixture hook smoke test" is dominating the prompt-frequency channel (37/90 prompts, 41%). It's a fixture — a stethoscope tapping the system to listen — but it's being counted as conversation. Analytics that read prompt-frequency assume each prompt is a unit of work; the fixture is breaking that assumption.
- **Hidden tension:** Every measurement of "what is Alex doing" includes the metronome. Frustration analysis, intent classification, β-mining — all of them get noisier because the fixture has no actor tag. This is a measurement-pollution problem, not a hook problem.
- **Subconscious learning:** Test traffic needs an `actor=test` or `tags=["fixture"]` mark at write-time so every downstream analyzer can filter it out cheaply. Once tagged, the real prompt patterns will look very different — likely sparser, more bursty, and easier to learn from. This is L-12's enforcement target.

## Cross-Pollination: Three Frictions, One Root

The three event-derived dreams (capsule gap, β chair, fixture heartbeat) feel separate. They aren't.

```
                       ┌───────────────────┐
                       │   advisory hooks  │
                       │   that don't      │
                       │   auto-correct    │
                       └─────────┬─────────┘
                                 │
              ┌──────────────────┼──────────────────┐
              │                  │                  │
        ┌─────┴─────┐      ┌─────┴─────┐      ┌─────┴─────┐
        │ /warp:    │      │ β-gate    │      │ cd-prefix │
        │ update    │      │ blocks    │      │ advisory  │
        │ no-graceful│      │ but no    │      │ warns but │
        │ -failure  │      │ pre-call  │      │ never     │
        │           │      │ prompt    │      │ rewrites  │
        └───────────┘      └───────────┘      └───────────┘
                       (8x, 17x, 7x — all warn, none fix)
```

### Deep Read
- **What emerged:** Every recurring friction in the event log is a *warn-only* rule. Each one fires, the agent shrugs, the agent retries the same pattern, the rule fires again. The rules are honest — they're flagging — but they're not closing the loop.
- **Hidden tension:** Warn-without-correct is a stable equilibrium. The rule keeps its conscience clean ("I flagged it!") while the friction keeps happening. The right model is: warn once, observe, then either auto-fix or escalate to block. Three warnings of the same kind in a session is a system fact, not an agent failure.
- **Subconscious learning:** Promote any advisory hook that has logged ≥ 3 identical fires in the same week to either auto-rewrite or block. This is a single architectural rule that subsumes L-9, L-10, L-11, L-12 — they're all instances of the same higher-order pattern: *advisory rules need an escalation ladder*. Worth lifting to a HYGIENE rule or even a meta-hook (`advisory-escalator.js`).
