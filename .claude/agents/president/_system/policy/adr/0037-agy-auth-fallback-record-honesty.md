# ADR-0037 — agy auth-fallback record honesty: the not-logged-in / eval-mode tell detector

**Status:** Accepted (2026-07-23; β DECIDE B/0.90 at the SP-20260723-002 plan→design boundary, `open_adr:true`, msg_id `bca79011-d4a1-4533-85e4-b74d130485f1`).
**Relates to:** ADR-0025 (provider-fallback masquerade / observed-completion record honesty — this extends it with an AUTH-fallback dimension). ADR-0031 / ED-060 / ED-230 (agy migration, the binding-on-a-verifiable-lane invariant). β P-059 (SP-719-L2 terminal-vs-transient).

## Context

An UNAUTHENTICATED agy serve (expired keyring) exits 0 with output, so `dispatch-agent.js`'s completion record stamped `fallback:false` — a **false-green**, found empirically this sprint. `observedCompletionFields` caught PROVIDER-level fallback (an openai run masquerading as agy — ADR-0025) but not agy's INTERNAL auth-fallback: agy served the CCPA default from eval-mode with `hasObserved:true` and no provider-fallback, so `fallback` stayed false. The tells that reveal the fallback (`eval-mode` / `expired=true` / `resolved-via-default` / `local-chrome-mode`) are written by agy to its **cli.log, NOT to stdout** (confirmed: the unauth serve's OUTPUT carried zero tells while the run-window LOG carried them). The completion record's `ok`/`fallback` gate the ED-060(c) liveness close (a tracker flip) and panel-3lab — so it is a record-trust surface.

The naive `expiry_date` check and the ambiguous "not logged into Antigravity" transient are both unreliable (agy emits the transient even on a genuine async-auth serve). The **terminal** tell set (`resolved-via-default | resolved-via-fallback | local-chrome-mode | eval-mode | authentication-failed | unauthorized | expired=true`) is the reliable discriminator — this serve carried them, so the keyring is definitively expired.

## Decision

1. **Single source** — `scripts/dispatch/agy-auth-tells.js` holds the terminal tell set + the run-window filter, extracted from `cert-attest.js` (which now `require`s them). One source for the dispatch detector + cert-attest + the ED-060 runbook — no drifting copy.
2. **runProvider computes `result.auth_fallback` for antigravity** via a UNION scan of stdout + stderr + the cli.log delta bound to THIS serve's window (`filterAgyLogToRunWindow`): `true` (a terminal tell in-window) / `"indeterminate"` (the cli.log was unreadable — fail-closed) / `false` (clean window; NOT a claim the serve was authenticated — never-claim-live).
3. **`--log-file` is REJECTED as the capture mechanism.** A custom `--log-file` itself BREAKS agy's keyring auth (cert-attest ~L494, DoE-confirmed live) — it would make every agy serve a false-RED, the enforcer causing the defect it detects. The shared-log delta-read bound to the run window is the correct correlation.
4. **dispatch-agent's `observedCompletionFields` ORs `auth_fallback` into `fallback`** (an auth-fallback forces `fallback:true`) AND stamps the explicit `auth_fallback` field on every agy serve — distinct from provider/quota fallback (ADR-0025) so cert-attest, the (c)-close consumer, and `gauntlet-verify --strict-fallback` can tell them apart. Settable-label-safe: the verdict derives from raw log BYTES, not a settable field.

## Consequences

- An unauthenticated agy serve can **never stamp `fallback:false` again** — the false-green is closed. The binding verdict routes to the verifiable openai/claude lane (panel degrades to the honest 2-family floor — the ADR-0031 invariant preserved; panel-3lab was never attestable from this record anyway, cert-attest fails-closed agy unconditionally).
- **P-059 CEILING (β load-bearing rider — must not be locked as permanent):** the blanket-fail on the terminal tells is sound ONLY while the keyring is expired (every serve genuinely unauthenticated — no authenticated serve to false-RED). POST-LOGIN, a genuine authenticated serve emits the TRANSIENT startup unauth lines (not-logged-in / defaulting-to-CCPA) BEFORE it authenticates — so a future blanket transient-fail would become the false-RED INVERSE, blocking the first real (c) close this seam exists to permit. The detector today correctly EXCLUDES the transients (only the terminal set fails), so it is fail-closed-safe now. The terminal-vs-transient partition refinement (a POSITIVE same-pid valid-auth matcher authored against a REAL captured authenticated-serve log — not a guessed format) is genuinely LOGIN-GATED and deferred as **ED-268**, tied to the operator-login / ED-060(c)-close event so it can't be silently forgotten.
- **Consumer note:** `auth_fallback` needs its OWN explicit gate — `gauntlet-verify:488` default-counts a fell-back record as "ran", so forcing `fallback:true` alone is silent past a default verify; the ED-060(c) close must check `auth_fallback` (or run `--strict-fallback`).
- **Two stale claims corrected** (this sprint's re-verification): the `GEMINI-DEEPCLEAN-AND-AGY-MIGRATION.md` "auth works from subprocess / no login needed" line and the 2026-07-20 CORRECTION-4 memory — the keyring IS expired (definitive `eval-mode` + `expired=true` terminal tells in the run window). ED-060(c) stays OPEN (operator interactive login surfaced: `agy -i` refreshes `~/.gemini/oauth_creds.json`). ED-230 served-model proof + panel-3lab stay OPEN/BLOCKED — unchanged by this sprint.
