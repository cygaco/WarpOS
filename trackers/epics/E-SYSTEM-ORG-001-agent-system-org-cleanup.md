## Tracker language convention (anti-deixis) — added 2026-06-08

**Problem.** Session-relative deixis ("this session", "next session", "currently", bare "now", "NEXT ACTION (session N)", "no X this session", "DONE this session") is ambiguous when read LATER: the referent of "this session" shifts to whoever is reading, so a *historical* status like "no execution this session" reads to the next session as a *present instruction* ("don't execute"). The session ordinal ("session 3/4") is also meaningless to a future reader. Confirmed recurring (RT-2026-06-05-stale-cutover-refs-alias-masked; the "why is this STILL not done" visibility gap).

**Rule — tracker prose is ABSOLUTE + state-chained, never bare session-relative:**
1. **Anchor every status to an absolute marker** — an ISO date (`YYYY-MM-DD`) and, where it exists, a 7–40-hex commit hash. Not "this session" → "as of 2026-06-08 @aa60e7e".
2. **State, don't narrate.** Use a State-Model value + a dated receipt. "DONE this session" → "DONE 2026-06-08 @<hash>". "no execution this session" → "Execution: NOT STARTED as of 2026-06-08" (dated past-tense, not a bare negative).
3. **NEXT ACTION is a standing imperative** — no session ordinal as the subject. "NEXT ACTION (session 4): do Y" → "NEXT ACTION (open as of 2026-06-08 @<hash>): do Y". Any future reader executes the same thing; the "as of" date makes staleness visible.
4. **Negatives are past-tense + dated**, never present-tense bare ("had not started as of <date>", not "no X this session").

**Enforcer (named; not yet built — ED-034):** a `session-relative-language` check in `scripts/trackers/validate.js` that flags a banned deictic phrase lacking an absolute anchor (ISO date or 7–40-hex hash) within the same clause; allowlisted exceptions (e.g. inside a fenced quote of an old handoff); ramped report-only → blocking after the existing high-read lines are converted. Until built, this rule is documented-but-unenforced (S-10).

## Handoff redesign (S-11) — design 2026-06-08 @9163f77 (build PENDING; RI-006)

**Bug (RI-006).** `scripts/hooks/session-stop.js` is wired to BOTH `Stop` (end of every reply) and `SessionEnd`, sharing ONE once-per-session sentinel (`.session-handoff-done`). `Stop` fires first (after reply #1), writes the handoff + flips the lock, so the `SessionEnd` trigger meant to capture the FINAL state never runs → the auto-handoff freezes at first-pause and is stale by close; `/clear`'s `SessionEnd` likewise skips → `/clear` captures nothing fresh. (Proof 2026-06-08: `handoff.md` mtime 08:15 claimed epic ~80% with the day's finished work listed as TODO, while the on-`main` reality at 17:30 was ~92% / D-3 done / 8 commits.) Since `TRACKER.md` is the curated source of truth, the handoff's redefined job is a **safety net** for tracker-drift + untracked work — carrying state between replies, at crash, at close (incl. accidental terminal close), and across `/clear`.

**Design — two layers.**
- **Layer 1 — cheap deterministic live-state** (`handoff-live.md`): written on EVERY `Stop` + `SessionEnd` (incl. `source:clear`); no LLM (~ms); atomic (temp+rename); SEPARATE file from the rich handoff (the per-turn writer must never touch the preserve-marked `handoff.md`). Content = GROUND TRUTH independent of the tracker: absolute ts + branch + HEAD; commits since `.session-start-commit`; **staged+unstaged files + diffstat** (the untracked-work signal); last 2–3 user asks (from the transcript the hook receives); current `in_progress` task + last action; task-list snapshot.
- **Layer 2 — rich narrative** (`handoff.md`): the AI-analyzed prose; `SessionEnd` + manual (`/session:handoff` / `/session:end`); preserve-marked; close-time only.
- **Coverage model.** A cheap snapshot after every turn auto-covers crash / accidental terminal close / `/clear` / close — all happen AFTER a completed turn that is already on disk, so the system stays ≤1 turn behind any disaster. The ONLY unrecoverable loss is a crash MID-turn (no hook observes an unfinished turn).

**Per-scenario cases.**
- **New session (`source:startup`).** A leftover PRIOR-session `handoff-live.md` is still on disk AND `startup` resets `.session-start-commit` → must NOT present the prior live-state as current (archive it timestamped; surface it only if its uncommitted files still exist on disk). Turn-1 gap: before the first `Stop`, only the prior snapshot exists → label every snapshot by `session_id` + absolute ts so it is never mistaken for current.
- **Resume session (`source:resume`).** `claude --resume <old-id>` into a runtime dir where a NEWER session last ran loads the WRONG baseline/live-state, because `.claude/runtime/` state is keyed to "last session in this folder", not to the resumed conversation → compare the hook payload `session_id` to the on-disk `.session-id`; on mismatch, re-baseline or warn LOUDLY (never silent-fallback). Baseline is correctly preserved on resume already.
- **Post-`/clear` (`SessionEnd(clear)` then `SessionStart(clear)`).** The conversation is GONE after `/clear`, so the handoff is the ONLY bridge and MUST be written BEFORE the wipe (capture at `SessionEnd(clear)` while context still exists) and read back by `SessionStart(clear)` — the current sentinel BLOCKS this write and must be removed. Ordering (SessionEnd write completes before SessionStart read) + atomic write are load-bearing. "/clear to switch tasks" vs "/clear to continue" is ambiguous → load the pre-`/clear` state but LABEL it ("ignore if you cleared to switch tasks"); the uncommitted-files list is useful either way. The baseline keeps counting across `/clear` (frame the result as "prior / pre-`/clear` work in this session", per the anti-deixis convention).
- **Cross-cutting / physics.** `SessionEnd` does NOT reliably fire on hard kill / accidental terminal close → those are covered by the last `Stop` snapshot ONLY (the rich Layer-2 is simply absent after a crash — state that plainly). The in-hook git must be read-only + short-timeout + **fail-open** (an `index.lock` from a concurrent git op must not hang the turn). `runtime/` is gitignored → the handoff never travels cross-machine; cross-machine continuity is the committed `TRACKER.md`'s job (keep the two roles distinct).

**4 LOAD-BEARING acceptance criteria (the S-11 DoD).** (1) **Per-`session_id` keying** — `.claude/runtime/` is single-tenant but the operator runs CONCURRENT sessions → they clobber `.session-id`/baseline/handoff today (a latent bug a per-turn writer AMPLIFIES); key files by the payload `session_id` (`handoff-live-<sid>.md`, `.session-start-commit-<sid>`), loader picks the matching sid else most-recent + labeled. (2) **`SessionEnd(clear)`→`SessionStart(clear)` ordering + atomic write** — makes `/clear` actually carry. (3) **Load-time freshness comparison** — when `handoff-live.md` is NEWER than `handoff.md`, the loader MUST surface the live-state delta ("⚠ uncommitted work newer than the last narrative"), else untracked work is invisible (the exact failure being prevented). (4) **Honest hard-kill framing** — cheap-snapshot-only after a crash; never imply otherwise.

**Build plan (additive-first; each step independently safe).** (1) Layer-1 writer as a NEW per-sid file that does not touch `handoff.md` (cannot break current behavior). (2) Watch across a few real sessions (freshness, no per-turn latency, no clobber). (3) Wire the `SessionStart` loader (freshness comparison) + the `/clear` bridge + RETIRE the freeze sentinel. (4) Fixture test: simulate `Stop`×N / `SessionEnd(clear)` / two concurrent sids / a planted crash-after-turn, asserting the live-state is correct + non-clobbered each time.

**Reuses existing infra (already correct):** `session-start.js` source-branching (`startup`/`resume`/`clear`/`compact`); `.session-id`; `.session-start-commit` (set on `startup` only, preserved across clear/resume/compact, so "commits since session start" already spans a `/clear` correctly). **Full design:** `runtime/notes/handoff-redesign-2026-06-08.md`.

## Persistent-team initialization (S-12) — design + spec (the once-and-for-all team-init fix)

**Bug (recurred 3 surfaces).** 2026-06-06 "where is the team?"; 2026-06-08 "why did you not dispatch the persistent team?" + "this isn't the persistent team I imagined — where's epsilon?" Traces: `RT-2026-06-08-memory-over-system`, `RT-2026-06-08-teaminit-fixdeep`, `RT-2026-06-08-dispatch-skip-recurrence`.

**Root cause (grounded in the SYSTEM, not memory).** `.claude/commands/mode/sprint.md` is complete and lesson-encoded — Step 1.75 spawns α+ε+β with the exact calls and even pre-states "NEVER defer the team … witnessed 2026-06-06." When a `/clear`'d kickoff names `/mode:sprint` as TEXT, the Skill is never invoked, Step 1.75 never runs, and the team is improvised from a lossy auto-memory summary → absent/wrong roster. **The operating loop permitted injected auto-memory to SUBSTITUTE for the system at the decision point.** Advisory injection alone is insufficient (proof: `session-start.js` already injects a MANDATORY dispatch-guide reference + the handoff on every cold start, and the skip STILL happened).

**Principle (now enforced by Layers a+b, not just doctrine):** *memory POINTS to the system; the system EXECUTES. A `/mode:X` in a prompt is a command to INVOKE, not context.*

**Canonical roster — the RIGHT faces per mode (single source for all three layers):**

| mode | lead | persistent faces to spawn | team name |
|---|---|---|---|
| sprint | α | **ε (epsilon) + β (beta)** | `<slug>-sprint` |
| adhoc | α | **β (beta) + γ (gamma)** | `<slug>-adhoc` |
| oneshot | — | δ IS the session (standalone) — no persistent team to spawn | — |
| solo | — | none | — |

**Fix shape:** system-level, at the action boundary, off persisted `mode.json` (which SURVIVES `/clear`, so it fires REGARDLESS of whether `/mode:sprint` is invoked). Three layers:

### Layer (a) — `session-start.js` MANDATORY system-sourced team-init directive · STATUS: BUILT 2026-06-08 (`456dfd5`)
- **Mechanism:** on `source ∈ {startup, clear}`, read `.claude/runtime/mode.json`; if `mode` is a team-mode (sprint/adhoc) AND the correct team is not live, inject — as `hookSpecificOutput.additionalContext`, FIRST (before all other context) — a `⛔ <MODE> MODE IS ACTIVE` directive carrying the EXACT Step-1.75 calls (`TeamCreate` + one `Agent(subagent_type:<face>, team_name, name, run_in_background, prompt:"STARTUP DIRECTIVE…")` per face, with each face's load list), framed as the MANDATORY first action.
- **Liveness check (also how the WRONG-ROSTER case is caught):** glob `~/.claude/teams/*/config.json` for a config with mtime < 24h whose `members` JSON contains ALL the mode's expected faces (`spec.faces.every(f => membersBlob.includes(f))`).
