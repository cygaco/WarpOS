# WarpOS 1.0 Charter

## Product definition

WarpOS is the operating layer for Warp Studios, an AI product foundry. It is not merely a Claude prompt system and not merely a code generator. It is a disciplined operating system for turning product ideas into shippable products with requirements, roles, dispatch, gates, launch readiness, founder guidance, memory, and learning.

## 1.0 definition

WarpOS 1.0 is ready when a clean installed product can move through:

```text
idea → canon → roadmap → sprint plan → dispatched build → review/gauntlet → launch readiness → founder setup → release → retro → learning promotion
```

without relying on chat memory, stale trackers, manual Alpha heroics, or unverified agent claims.

## 1.0 is not

- every possible feature finished
- native/mobile packaging fully solved
- a permanent Claude-team architecture
- an all-agent autonomous company with no human gates
- a pile of docs without enforcement
- a founder panel mockup without a store
- a dispatch matrix that works only for Claude

## System identity

```text
Alex        = president identity / product-foundry operator face
Alpha       = default human-facing architect and orchestrator
Beta        = judgment / decision service
Epsilon     = sprint conductor
Gamma/Delta = mode coordinators
Workers     = disposable or wave-resident executors
WarpOS      = durable company state and enforcement layer
```

## Core invariants

- Written state outranks chat memory.
- Role identity is separate from provider runtime.
- Model runtimes are replaceable.
- Every externalized task returns evidence.
- Every repeated failure becomes a pack, check, hook, template, or Beta rule.
- Every shipped product gets a production trust envelope.
- Every human/founder action is surfaced clearly and tracked.

## Product-foundry definition of done

A product is not done when it compiles. It is done when:

- thesis, user, JTBD, MVP scope, and non-goals are clear
- PRD, UX, architecture, and analytics are traceable
- implementation maps to requirements and tests
- security/privacy risks are reviewed
- launch docs and support flows exist
- founder-owned setup is visible and evidence-backed
- metrics are live or explicitly deferred
- QA and red-team review pass
- release metadata is consistent
- retrospective promotes lessons into WarpOS
- next decision is clear: iterate, pivot, pause, or kill

## 1.0 delivery model

Deliver as packs, not one-off patches:

```text
Pack = manifest + templates + scripts + checks + hooks + docs + fixtures + gates + evidence shape
```

The first critical packs are:

- Truth/Release Pack
- Instruction Interop Pack
- WorkOrder/Envelope Pack
- SprintRoom Pack
- Dispatch/Liveness Pack
- Sprint Compiler Pack
- Founder Panel Pack
- WebApp Production Baseline Pack
- Supabase/Next Security Pack
- Demo/MVP/Launch Gates Pack
- Observability/Memory/Learning Pack
- Hidden Evals Pack
